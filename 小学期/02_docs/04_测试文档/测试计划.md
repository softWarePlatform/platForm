# 在线教学与实训平台测试计划

文档编号：`TEACHING-PLATFORM-TEST-PLAN-2026-V1.0`  
适用版本：最终微服务版本（基线提交以执行报告记录的 Git SHA 为准）  
计划/执行窗口：2026-08-25～2026-09-03  
状态：最终版

## 1. 目的与质量目标

本计划用于统一在线教学与实训平台的测试范围、环境、数据、执行顺序和验收标准。目标是确认 UC01～UC10 主业务链路可用，微服务边界和异常降级符合设计，部署后可观测、可回滚，并以可重复的原始报告支持最终验收。

质量目标：P0/P1 缺陷清零；UC01～UC10 主流程全部通过；自动化测试、构建、数据库 migration、健康检查均为绿；性能测试至少重复 3 次并保留 QPS、Avg、P95、错误率和资源快照。

## 2. 测试依据与范围

测试依据包括需求说明书、UC01～UC10 用例、概要/详细设计、最终服务接口清单、数据库 Schema/migration、Kubernetes 清单和 CI/CD 工作流。需求与用例材料位于 `小学期/02_docs/01_需求与用例`，追溯表位于 `小学期/02_docs/05_追溯表`。

范围内功能：

- UC01 选课与课表同步；UC02 课程创建、配置与发布；
- UC03 公告发布/阅读；UC04 课程资料上传/下载；
- UC05 作业发布、提交、批改、成绩发布；UC06 实验自动/人工评测；
- UC07 智能组卷、答题、评分和错题反馈；UC08 课程讨论；
- UC09 成绩汇总与权重；UC10 管理员用户、选课阶段和审计；
- API Gateway 路由、服务间鉴权/超时/失败关闭、数据库访问、Redis 队列；
- Compose/Kubernetes 部署、migration、健康检查、CI 失败阻断和应用镜像回滚；
- 基础性能、安全、浏览器兼容性和恢复能力。

范围外：第三方大模型答案质量、真实生产容量预测、云厂商 SLA、移动原生客户端、未配置浏览器/操作系统组合。外部 AI 未配置时只验证规则降级和错误处理。

## 4. 测试数据

固定账号由 `docker compose --profile tools run --rm course-seed` 写入 Course Service 数据库。兼容 API 的历史全量数据由 `docker compose --profile tools run --rm seed` 写入兼容库。两个命令都会清理各自数据库的业务表，仅允许在可重置的演示/测试库执行。

| 角色 | 账号 | 密码 |
| --- | --- | --- |
| 管理员（最终 Gateway） | `admin@course.local` | `Course123456` |
| 教师（最终 Gateway） | `teacher@course.local` | `Course123456` |
| 学生（最终 Gateway） | `student@course.local`、`student2@course.local` | `Course123456` |
| 兼容 API 历史账号 | `admin@demo.local`、`teacher@demo.local`、`student@demo.local` 等 | `Demo123456` |

最终 Gateway 的固定基线为 4 个账号、正式选课阶段、默认班和 2 门课程。需要跨三个业务服务的丰富数据时，执行 `npm run qa:seed:rich` 创建带时间戳的隔离 fixture（3 教师、18 学生、6 课程及关联作业/实验/练习/讨论），再用 `npm run qa:seed:rich:verify` 验证。兼容库的历史基线为 12 门课程、5 名教师、20 名学生和 1 名管理员。自动化测试新增数据必须使用时间戳/随机 ID，并在 `finally` 或测试 teardown 中清理；需要修改课程说明/成绩权重的场景须恢复原值。

## 5. 测试策略与执行入口

| 层级 | 重点 | 自动化入口 | 主要证据 |
| --- | --- | --- | --- |
| 静态/构建 | TypeScript、Compose、Kustomize、镜像构建前置 | `npm run build`、`docker compose config --quiet`、`kubectl kustomize k8s/monolith` | 控制台日志/CI 日志 |
| 单元测试 | 认证、权限、课表、作业、实验、练习、通知、资料等规则 | `npm run test:unit`、`npm run test:services` | 测试框架输出 |
| DAO 集成 | Prisma 与真实 PostgreSQL migration 后的数据读写 | `npm run test:dao` | DAO 测试输出 |
| API | UC01～UC10 主流程及 400/401/403 等异常流程 | `npm run test:api` | `api-use-cases.json` |
| E2E | 跨角色、跨资源的 10 条完整业务链路和清理 | `npm run test:e2e` | `e2e-*.json` |
| 微服务契约 | Gateway 路由和 Course/Homework/Lab 跨服务正常、超时、空结果、服务不可用 | `npm run qa:microservices`、`npm run qa:cross-service-resilience` | `test-results/qa` JSON/日志 |
| 部署/恢复 | migration 顺序、rollout、健康检查、HPA、指定 SHA 回滚 | `scripts/deploy-k8s.ps1`、`scripts/health-check.ps1`、`scripts/rollback-k8s.ps1` | deployment/rollback evidence |
| 性能 | 3 个核心查询接口，同机同数据至少 3 轮 | `小学期/04_tests/performance/run-performance.ps1` | 逐请求 JSON、资源快照、分析 |
| 安全/兼容 | JWT、越权、注入/XSS、响应头、Chrome/Edge/Firefox | 专项脚本与人工 UI 走查 | JSON、截图、最终报告 |

执行顺序为：环境校验 → migration/seed → 构建 → 单元/服务测试 → DAO → 启动服务并等待 ready → API → E2E/跨服务 → 性能与恢复 → 汇总。任一步返回非零时不得将后续结果标记为该版本通过。

## 6. 用例优先级

| 优先级 | 范围 | 执行策略 |
| --- | --- | --- |
| P0 | 登录鉴权、选课、课程访问、作业/实验提交与成绩、数据库 migration、readiness | 每次合并/发布必跑，失败立即阻断 |
| P1 | 公告、资料、练习、讨论、管理员审计、服务间异常、E2E 清理 | 每次 CI 与发布候选版本必跑 |
| P2 | 性能趋势、安全抽检、浏览器兼容、HPA/故障演练 | 最终验收及重大基础设施变更时执行 |
| P3 | UI 文案、非关键布局和探索性建议 | 时间允许时执行并记录 |

## 7. 准入与退出准则

准入条件：需求和接口范围已冻结；测试环境可访问；四组数据库 migration 成功；标准 seed 或等价隔离 fixture 可用；所有服务 `/health/ready` 返回 2xx；测试脚本与报告目录可写。

退出条件：

- 构建、Unit、服务测试、DAO、API、UC01～UC10 E2E 全部通过；
- 所有 P0/P1 缺陷关闭且完成回归，P2/P3 缺陷有负责人、影响和处置说明；
- Compose/Kubernetes 部署健康检查通过，CI 能证明失败阻断后续镜像/部署；
- 性能测试至少 3 轮，错误率和响应时间有原始数据及解释；
- 测试报告、追溯表、原始 JSON/日志/截图已归档，任何未执行项明确标为“未执行/阻断”。

若存在环境原因导致某项无法执行，只能给出“有条件通过”或“阻断”，不得以历史版本结果替代当前版本。

## 8. 缺陷管理

缺陷至少记录：ID、发现版本/SHA、环境、前置条件、复现步骤、预期/实际结果、日志/截图、严重级别、负责人、状态和回归结果。

| 级别 | 判定 | 响应 |
| --- | --- | --- |
| P0 | 数据丢失、安全破坏、系统不可用、核心流程完全中断 | 立即停止发布，修复后全量回归 |
| P1 | 主要功能不可用且无可接受绕行 | 当前版本不得发布，修复并针对性+相关链路回归 |
| P2 | 局部功能/兼容/性能问题，有明确绕行 | 评估后可有条件验收，必须纳入缺陷清单 |
| P3 | 轻微文案、样式或改进建议 | 进入维护迭代 |

状态流转：新建 → 已确认 → 修复中 → 待回归 → 已关闭；无法修复的项只能转为“已知/延期”，并记录批准人和风险，不得直接关闭。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Docker Hub/GHCR 网络或证书异常 | 镜像不能构建/拉取 | 保留错误原文；修复代理/证书后重跑，不用旧镜像冒充 |
| 端口 5432/6379/5173 冲突 | 环境无法启动或连接错误实例 | 使用 `.env` 的 `POSTGRES_PORT`/`REDIS_PORT`，启动前检查端口 |
| 全局限流产生 429 | 压测错误率升高 | 固定并记录限流参数；429 计入错误并单独分析 |
| 测试数据污染 | 重跑不稳定、误判 | 隔离 fixture、时间戳 ID、finally 清理、变更后恢复原值 |
| 外部 AI 不可用 | AI 场景不稳定 | 验证超时和规则降级；不把模型内容质量作为发布门禁 |
| 应用镜像回滚但 Schema 不兼容 | 回滚后 API 失败 | 采用扩展-迁移-收缩；回滚脚本不自动回退数据库 |
| 远程 CI 元数据缺失 | 无法证明云端流水线运行 | 报告标记为本地证据；由仓库管理员补 Actions URL、run ID、SHA |
