# 10 对象级顺序图（第二批）

- 任务：基于组件级交互细化到具体对象（类实例）之间的消息传递
- 用例总数：10
- 本批完成：**3 张**（UC02、UC07、UC10）
- 累计完成：**7/10 张**（达到累计 2/3 的阶段目标）
- 组件级输入：[`05-关键调用链与关系图.md`](./05-关键调用链与关系图.md) 及各用例说明中的组件级流程

## 1. 建模约定

- 参与者使用 `对象名:类名` 表示，明确同一类在运行时的具体实例。
- React 函数组件按边界对象建模，Fastify 路由插件按控制对象建模，函数模块按领域服务对象建模。
- `prisma:PrismaClient` 代表数据访问对象，消息中写出实际 Prisma Model 方法。
- `alt` 表示互斥分支，`opt` 表示可选流程，`loop` 表示迭代处理，`par` 表示并行查询，`rect` 表示事务边界。
- 图中只描述当前代码已经存在的行为；未实现的能力以 `Note` 明确标识。

## 2. OBJ-UC02 创建、配置并发布课程

### 2.1 对象映射

| 对象实例 | 类/模块 | 类型 | 职责 |
| --- | --- | --- | --- |
| `teacher` | `User` | Actor/Entity | 创建并管理本人课程的教师 |
| `teachingHub` | `TeachingHub` | Boundary | 收集课程基础信息并发起创建请求 |
| `courseManage` | `CourseManage` | Boundary | 编辑课程配置、课表和发布状态 |
| `api` | `AxiosInstance` | Gateway | 附加 JWT，调用课程 API |
| `courseController` | `CoursesRoutes` | Control | 角色校验、Zod 校验、权限判断和响应映射 |
| `enrollmentSchema` | `CourseEnrollmentSchema` | Value/Validator | 校验课程代码、容量、学分和选课属性 |
| `scheduleCodec` | `ScheduleSlotsService` | Service | 校验并序列化 `ScheduleSlot[]` |
| `prisma` | `PrismaClient` | Repository | 事务写入 `Course` 和 `EnrollmentLog` |
| `course` | `Course` | Entity | 保存课程配置和发布状态 |

```mermaid
sequenceDiagram
  autonumber
  actor teacher as teacher:User
  participant hub as teachingHub:TeachingHub
  participant manage as courseManage:CourseManage
  participant api as api:AxiosInstance
  participant controller as courseController:CoursesRoutes
  participant schema as enrollmentSchema:CourseEnrollmentSchema
  participant schedule as scheduleCodec:ScheduleSlotsService
  participant prisma as prisma:PrismaClient
  participant course as course:Course

  teacher->>hub: fillCourseForm(title, code, credits, capacity, scheduleSlots)
  hub->>api: post(/courses, createCourseDto)
  api->>controller: POST /courses + Bearer token
  controller->>controller: authRequired(TEACHER, ADMIN)
  controller->>schema: safeParse(createCourseDto)
  schema-->>controller: parsed fields | validation errors

  alt 无权限或字段不合法
    controller-->>api: HTTP 403/400 {error}
    api-->>hub: reject(error)
    hub-->>teacher: 显示权限或字段错误
  else 校验通过
    opt 提供课表时段
      controller->>schedule: serializeScheduleSlots(scheduleSlots)
      schedule-->>controller: scheduleSlotsJson
    end

    rect rgb(238, 242, 255)
      Note over controller,prisma: Prisma 事务：课程与创建日志保持一致
      controller->>prisma: $transaction(callback)
      prisma->>course: course.create({teacherId,published:false,...})
      course-->>prisma: createdCourse
      prisma->>prisma: enrollmentLog.create(action=COURSE_CREATE, courseId)
      prisma-->>controller: createdCourse
    end

    alt courseCode 唯一约束冲突（P2002）
      controller-->>api: HTTP 409 课程代码已存在
      api-->>hub: reject(conflict)
      hub-->>teacher: 提示更换课程代码
    else 创建成功
      controller-->>api: HTTP 200 {course}
      api-->>hub: createdCourse
      hub-->>teacher: 显示创建成功并进入课程管理
    end
  end

  teacher->>manage: editCourse(fields, scheduleSlots, published=true)
  manage->>api: patch(/courses/{courseId}, updateCourseDto)
  api->>controller: PATCH /courses/{id}
  controller->>prisma: course.findUnique(id)
  prisma-->>controller: course

  alt 非课程教师且非管理员
    controller-->>api: HTTP 403 无权修改该课程
    api-->>manage: reject(error)
  else 所有者或管理员
    controller->>schema: safeParse(updateCourseDto)
    opt 更新课表
      controller->>schedule: serializeScheduleSlots(scheduleSlots)
      schedule-->>controller: scheduleSlotsJson
    end
    controller->>course: course.update({id, fields, published:true})
    course-->>controller: publishedCourse
    controller-->>api: HTTP 200 {course}
    api-->>manage: publishedCourse
    manage-->>teacher: 显示“已保存并发布”
  end
```

### 2.2 关键方法逻辑

1. `TeachingHub` 使用 `POST /courses` 创建课程，创建时默认 `published=false`，也允许请求显式给出发布值。
2. `CoursesRoutes` 将基础字段校验与 `courseEnrollmentFieldsSchema` 合并，并通过 `scheduleSlotsBodySchema` 校验课表结构。
3. `serializeScheduleSlots()` 把 `ScheduleSlot[]` 转为 `Course.scheduleSlotsJson`。
4. `course.create()` 与 `enrollmentLog.create(COURSE_CREATE)` 位于同一 Prisma 事务中，任一失败则整体回滚。
5. `PATCH /courses/:id` 先检查课程所有者；教师只能修改本人课程，管理员可以修改任意课程。

## 3. OBJ-UC07 练习组卷、作答、批改与错题更新

### 3.1 对象映射

| 对象实例 | 类/模块 | 类型 | 职责 |
| --- | --- | --- | --- |
| `student` | `User` | Actor/Entity | 选择组卷模式、作答并提交 |
| `practicePage` | `CoursePractice` | Boundary | 选择模式、标签、难度和题量 |
| `sessionPage` | `PracticeSession` | Boundary | 展示题目、保存答案并展示结果 |
| `api` | `AxiosInstance` | Gateway | 调用练习相关 HTTP API |
| `practiceController` | `PracticeRoutes` | Control | 课程访问校验、会话权限和状态控制 |
| `picker` | `PracticePickService` | Service | 按 SMART/BY_TAG/WRONG_BOOK/CUSTOM 选择题目 |
| `grader` | `PracticeGradeService` | Service | 按题型判定答案并生成得分明细 |
| `wrongAnalyzer` | `WrongAnswerAnalyzer` | Service | 生成错因摘要和错题内容 |
| `prisma` | `PrismaClient` | Repository | 保存会话、题目项、统计和错题本 |
| `session` | `PracticeSession` | Entity | 保存本次练习状态和总分 |
| `item` | `PracticeSessionItem` | Entity | 保存单题答案、耗时和批改结果 |
| `wrongEntry` | `WrongBookEntry` | Entity | 保存学生尚未掌握的错题 |

```mermaid
sequenceDiagram
  autonumber
  actor student as student:User
  participant page as practicePage:CoursePractice
  participant sessionPage as sessionPage:PracticeSession
  participant api as api:AxiosInstance
  participant controller as practiceController:PracticeRoutes
  participant picker as picker:PracticePickService
  participant grader as grader:PracticeGradeService
  participant analyzer as wrongAnalyzer:WrongAnswerAnalyzer
  participant prisma as prisma:PrismaClient
  participant session as session:PracticeSession
  participant item as item:PracticeSessionItem
  participant wrong as wrongEntry:WrongBookEntry

  student->>page: startSession(mode, count, tags, difficulty)
  page->>api: post(/courses/{courseId}/practice/sessions, config)
  api->>controller: POST sessions + Bearer token
  controller->>controller: requireCourseView(courseId, userId, role)
  controller->>controller: sessionSchema.safeParse(config)

  alt 无课程访问权、教师发起学生练习或参数非法
    controller-->>api: HTTP 400/403 {error}
    api-->>page: reject(error)
  else 可以组卷
    controller->>picker: pickQuestionsForSession(courseId,userId,mode,count,filters)
    alt mode=WRONG_BOOK
      picker->>prisma: wrongBookEntry.findMany(userId, mastered=false)
    else mode=SMART
      picker->>prisma: practiceSessionItem.findMany(历史薄弱项)
      picker->>prisma: practiceQuestion.findMany(已审核且答案已确认)
    else mode=BY_TAG/CUSTOM
      picker->>prisma: practiceQuestion.findMany(tag/difficulty filters)
    end
    prisma-->>picker: selectedQuestions[]
    picker-->>controller: questions[]

    alt 没有可用题目
      controller-->>api: HTTP 400 {筛选或标准答案提示}
      api-->>page: 显示无可用题目
    else 题目可用
      controller->>session: practiceSession.create(status=IN_PROGRESS, items.create[])
      session->>prisma: INSERT PracticeSession + PracticeSessionItem[]
      prisma-->>controller: session + ordered items
      controller-->>api: HTTP 200 {session}
      api-->>page: sessionId
      page->>sessionPage: navigate(/practice/session/{sessionId})
    end
  end

  loop 学生逐题作答
    student->>sessionPage: saveAnswer(itemId, answer, timeSpentMs)
    sessionPage->>api: patch(/practice/sessions/{sid}/items/{iid}, answerDto)
    api->>controller: PATCH session item
    controller->>session: practiceSession.findUnique(sessionId)
    alt 非会话所有者或会话不再是IN_PROGRESS
      controller-->>api: HTTP 403/400 {error}
    else 可保存
      controller->>item: practiceSessionItem.update(answerJson,timeSpentMs)
      item->>prisma: UPDATE PracticeSessionItem
      controller-->>api: HTTP 200 {itemId}
    end
  end

  student->>sessionPage: submitSession()
  sessionPage->>api: post(/practice/sessions/{sessionId}/submit)
  api->>controller: POST submit
  controller->>session: practiceSession.findUnique(include items.question)

  alt 已提交或不是会话所有者
    controller-->>api: HTTP 400/403 {error}
  else status=IN_PROGRESS
    loop 遍历每个题目项
      controller->>grader: gradePracticeAnswer(question, answerJson)
      grader-->>controller: {correct, score, detail}
      controller->>item: update(correct,score,resultJson)
      controller->>prisma: practiceQuestion.update(attemptCount,correctCount,totalTimeMs)
      alt 回答正确
        controller->>wrong: wrongBookEntry.deleteMany(userId,questionId,mastered=false)
      else 回答错误
        controller->>analyzer: analyzeWrongAnswer(question, answerJson)
        analyzer-->>controller: wrongContent
        controller->>wrong: findFirst(userId,questionId)
        alt 已有错题记录
          controller->>wrong: update(content,mastered=false)
        else 首次答错
          controller->>wrong: create(userId,courseId,questionId,content)
        end
      end
    end
    controller->>session: update(status=GRADED,score,submittedAt,gradedAt)
    session->>prisma: UPDATE PracticeSession
    controller-->>api: HTTP 200 {score,maxScore,status,removedFromWrongBook}
    api-->>sessionPage: gradingResult
    sessionPage-->>student: 显示逐题结果、总分和错题变化
  end
```

### 3.2 关键方法逻辑

1. `pickQuestionsForSession()` 根据模式选择题库来源；SMART 使用历史薄弱项，WRONG_BOOK 使用未掌握错题，标签模式使用标签过滤。
2. 会话创建时通过嵌套 `items.create` 一次生成 `PracticeSession` 与有序的 `PracticeSessionItem[]`。
3. 作答接口同时验证 `session.userId` 和 `session.status===IN_PROGRESS`，防止越权修改或重复作答。
4. `gradePracticeAnswer()` 逐题返回正确性、分数和结果明细；控制器累计总分并更新题目尝试次数、正确次数和总耗时。
5. 正确题从未掌握错题本删除；错误题按“学生+题目”更新或创建 `WrongBookEntry`。
6. 全部题目处理完成后，会话统一变为 `GRADED` 并写入 `submittedAt`、`gradedAt` 和总分。

## 4. OBJ-UC10 管理选课阶段、特殊加退课与操作记录

### 4.1 对象映射

| 对象实例 | 类/模块 | 类型 | 职责 |
| --- | --- | --- | --- |
| `admin` | `User` | Actor/Entity | 配置阶段、执行特殊加退课并查看日志 |
| `classServePage` | `AdminClassServe` | Boundary | 编辑选课阶段并提交特殊加退课请求 |
| `usersPage` | `AdminUsers` | Boundary | 查询用户列表和指定用户操作记录 |
| `logsPage` | `AdminLogs` | Boundary | 查询管理员操作日志 |
| `api` | `AxiosInstance` | Gateway | 附加管理员 JWT 并调用 API |
| `enrollmentController` | `EnrollmentRoutes` | Control | 校验阶段配置，调度管理员加退课 |
| `adminController` | `AdminRoutes` | Control | 查询用户、用户日志和审计视图 |
| `enrollmentService` | `EnrollmentService` | Service | 复用选课、退课、日志和候补递补规则 |
| `prisma` | `PrismaClient` | Repository | 读写阶段、用户、选课、日志和通知 |
| `period` | `EnrollmentPeriod` | Entity | 保存学期选课阶段和开放时间窗 |
| `enrollmentLog` | `EnrollmentLog` | Entity | 保存选课及管理员特殊加退课事件 |
| `notification` | `SiteNotification` | Entity | 当前管理员审计视图的数据来源 |

```mermaid
sequenceDiagram
  autonumber
  actor admin as admin:User
  participant classPage as classServePage:AdminClassServe
  participant usersPage as usersPage:AdminUsers
  participant logsPage as logsPage:AdminLogs
  participant api as api:AxiosInstance
  participant enrollmentCtl as enrollmentController:EnrollmentRoutes
  participant adminCtl as adminController:AdminRoutes
  participant service as enrollmentService:EnrollmentService
  participant prisma as prisma:PrismaClient
  participant period as period:EnrollmentPeriod
  participant log as enrollmentLog:EnrollmentLog
  participant notice as notification:SiteNotification

  admin->>classPage: editPeriod(phase, openAt, closeAt, confirmDeadline)
  classPage->>api: put(/enrollment/period, periodDto)
  api->>enrollmentCtl: PUT /enrollment/period + Bearer token
  enrollmentCtl->>enrollmentCtl: authRequired(ADMIN) + schema.safeParse()

  alt 非管理员、参数非法或closeAt<=openAt
    enrollmentCtl-->>api: HTTP 403/400 {error}
    api-->>classPage: 显示配置失败原因
  else 校验通过
    enrollmentCtl->>period: enrollmentPeriod.upsert(semesterKey, phase, timeWindow)
    period->>prisma: INSERT or UPDATE EnrollmentPeriod
    prisma-->>enrollmentCtl: savedPeriod
    enrollmentCtl-->>api: HTTP 200 {period}
    api-->>classPage: savedPeriod
    classPage-->>admin: 显示阶段配置成功
  end

  admin->>classPage: manualEnroll(userId, courseId)
  classPage->>api: post(/enrollment/admin/enroll, {userId,courseId})
  api->>enrollmentCtl: POST admin/enroll
  enrollmentCtl->>enrollmentCtl: authRequired(ADMIN)
  enrollmentCtl->>service: enrollStudent(userId,courseId,{operatorId:adminId,skipWindowCheck:true})
  service->>prisma: course.findUnique(courseId)
  service->>prisma: enrollment.findUnique(userId_courseId)

  alt 课程不可选或已重复选课
    service-->>enrollmentCtl: throw 404/409
    enrollmentCtl-->>api: HTTP 404/409 {error}
  else 可以特殊加课
    service->>prisma: enrollment.create(userId,courseId)
    service->>log: enrollmentLog.create(action=ADMIN_ENROLL,operatorId=adminId)
    log->>prisma: INSERT EnrollmentLog
    service-->>enrollmentCtl: enrollment
    enrollmentCtl-->>api: HTTP 200 {enrollment}
    api-->>classPage: 显示加课成功
  end

  opt 管理员特殊退课
    admin->>classPage: manualDrop(userId, courseId)
    classPage->>api: post(/enrollment/admin/drop, {userId,courseId})
    api->>enrollmentCtl: POST admin/drop
    enrollmentCtl->>service: dropStudent(userId,courseId,{operatorId:adminId,skipWindowCheck:true})
    service->>prisma: enrollment.delete(id)
    service->>log: enrollmentLog.create(action=ADMIN_DROP,operatorId=adminId)
    service->>service: promoteWaitlistForCourse(courseId)
    service-->>enrollmentCtl: completed
    enrollmentCtl-->>api: HTTP 200 {ok:true}
  end

  par 查询用户和指定用户日志
    admin->>usersPage: openUserLogs(userId)
    usersPage->>api: get(/admin/users/{userId}/logs)
    api->>adminCtl: GET user logs
    adminCtl->>prisma: user.findUnique(userId)
    adminCtl->>prisma: enrollmentLog.findMany(userId,take=50)
    adminCtl->>prisma: courseAnnouncement.findMany(authorId,take=20)
    adminCtl->>prisma: siteNotification.findMany(userId,take=50)
    prisma-->>adminCtl: user + enrollment + announcements + notifications
    adminCtl-->>api: HTTP 200 {user,logs}
    api-->>usersPage: renderUserLogs()
  and 查询管理员审计视图
    admin->>logsPage: loadAuditLogs()
    logsPage->>api: get(/admin/audit)
    api->>adminCtl: GET /admin/audit
    adminCtl->>notice: siteNotification.findMany(type=ADMIN_ACTION)
    notice->>prisma: SELECT SiteNotification
    prisma-->>adminCtl: auditRows
    adminCtl-->>api: HTTP 200 {logs}
    api-->>logsPage: renderAuditLogs()
  end

  Note over admin,prisma: 当前User没有enabled/status字段，也没有启用/禁用接口；该能力不能进入成功消息链。
  Note over adminCtl,notice: /admin/audit当前由SiteNotification(type=ADMIN_ACTION)拼装，不是独立不可篡改审计表。
```

### 4.2 关键方法逻辑与实现边界

1. `PUT /enrollment/period` 只允许管理员访问，并拒绝 `closeAt<=openAt` 的时间窗。
2. 管理员加退课复用 `enrollStudent()` 和 `dropStudent()`，通过 `skipWindowCheck=true` 绕过普通选课窗口，通过 `operatorId` 写入 `ADMIN_ENROLL/ADMIN_DROP`。
3. 特殊退课后仍调用 `promoteWaitlistForCourse()`，保证释放名额后候补队首能够自动入选。
4. 用户日志接口聚合 `EnrollmentLog`、公告和 `SiteNotification`，并不是只查询单一日志表。
5. `/admin/audit` 当前从 `SiteNotification(type=ADMIN_ACTION)` 形成展示数据，没有独立 `AuditLog` 实体。
6. 当前 `User` 没有启用/禁用状态字段和对应接口，因此 UC10 仍是部分实现；顺序图不虚构该调用。
