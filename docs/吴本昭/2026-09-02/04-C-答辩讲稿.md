## 2. C 自己的讲稿（可照读）

### 开场（页 02–03）

我们按域拆成三个进程，而不是按页面拆。课程域在 Course `:3001`，作业成绩在 Homework `:3002`，实验练习在 Lab `:3003`。浏览器只访问 API Gateway `:3081`，Vite 开发代理也是打到网关。作业库是独立的 `homework_grade_service`，代码里没有 Course、Lab 的 Prisma 模型。

### 作业服务（页 04）

UC05 主路径在作业服务：创建、发布、提交、批改、发布成绩。权限和名单走 Course 的内部接口 `GET /internal/courses/:id/access/:userId`，写操作 fail-closed：下游超时或 5xx 是 503，不是当成未选课放行。通知带 `Idempotency-Key`，失败不回滚发布。

综合成绩 UC09：作业分在本库，实验分调 Lab 的 `lab-gradebook`。Lab 没起来时 `labStatus=UNAVAILABLE`，`totalScore` 是 `null`，只给 `provisionalTotal`。缺的实验分不当 0。

错题写入已经按 B 冻结的 PUT/DELETE 接好；真服务要等 `:3003`。读错题走网关 `/api/wrong-book/**` 到 Lab，不走作业服务。

### 网关（页 05）

网关按路径分流：`/api/homework/**` 和课程下的 `homework` / `gradebook` 打到作业；登录、选课打到课程；实验、错题本打到 Lab。每条请求带 `X-Request-ID`，下游挂了返回 502 `{ code: "BAD_GATEWAY", message, requestId }`。`/internal/**` 不对浏览器开放。

### 演示（页 11，配合 02 文档）

环境：Course、Homework、Gateway 在跑，Lab 今天可以保持没起，等价于停 Lab。

1. `GET /api/labs` → 502，`requestId` 在头和 JSON 里一致。
2. 教师走前端或网关跑 UC05：发布作业、学生提交、批改、发布成绩。
3. `GET /api/courses/:id/gradebook` → 200，`labStatus=UNAVAILABLE`，`totalScore=null`。

不要说「实验 0 分」。要说「实验不可用，总评降级」。
