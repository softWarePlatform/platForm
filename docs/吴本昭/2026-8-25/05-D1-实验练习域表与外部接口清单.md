## 2. 数据表归属（lab-practice-service）

表名取 Prisma 模型名。拆分后只保留业务 ID 引用，不保留跨 Schema 外键。

### 2.1 实验与评测（UC06）

| 模型 | 主键 | 关键字段 | 当前 Prisma 外键 | 拆分后 |
| --- | --- | --- | --- | --- |
| `LabSet` | `id` | `courseId`、`title`、`description`、`startAt`、`dueAt`、`allowMakeup`、`makeupDueAt`、`outsideAccessMode`（`BLOCK`/`VIEW_ONLY`）、`sortOrder`、`allowedFileExtensions`、`judgeMode`、`allowedLanguages`、`maxReturnCount` | `Course` | 只存 `courseId` |
| `LabReminderSent` | `id` | `labSetId`、`userId`、`kind`（`BEFORE_START`/`BEFORE_END`）、`sentAt`；唯一约束 `(labSetId, userId, kind)` | `LabSet`、`User` | `userId` 无外键 |
| `Lab` | `id` | `courseId`、`labSetId`、`title`、`description`、`descriptionMd`、`language`、`starterCode`、`judgeMode`（可空，继承集）、`allowedLanguages`、`allowedFileExtensions` | `Course`、`LabSet` | 只存 `courseId` |
| `LabFile` | `id` | `labId`、`title`、`fileName`、`storedPath`、`mimeType`、`sizeBytes`、`uploadedById` | `Lab`、`User` | `uploadedById` 无外键 |
| `TestCase` | `id` | `labId`、`input`、`expected`、`hidden`、`weight` | `Lab` | 本域内 |
| `Submission` | `id` | `labId`、`userId`、`submissionKind`（`CODE`/`FILE`）、`language`、`code`、`fileName`、`fileStoredPath`、`status`、`score`、`resultJson`、`teacherComment`、`returnReason`、`returnCount`、`returnedAt`、`gradedById`、`gradedAt` | `Lab`、`User`×2 | `userId`/`gradedById` 无外键 |

`SubmissionStatus`：`PENDING` → `JUDGING` → `ACCEPTED` / `WRONG_ANSWER` / `ERROR` / `TIMEOUT`；手动批改为 `PENDING_REVIEW`。  
`JudgeMode`：`AUTO` 入队 Worker；`MANUAL` 不入队，状态 `PENDING_REVIEW`。

成绩规则（与 `lab-grades.ts`、UC09 一致，拆分后由内部接口输出）：

- 每题取该学生各次提交的**最高分**；无提交为 `null`。
- 实验集均分 = 集内已有分数题目最高分的算术平均。
- 课程实验均分 = 各实验集 `setAverage` 的算术平均（仅统计有均分的集）。
- 总评权重当前在 `Course.labWeight` / `homeworkWeight`，**不归本域**；由 homework-grade-service 的 `GradingConfig` 持有。

### 2.4 共享与越界（必须在拆分前拍板）

| 对象 | 现状 | 建议 |

## 6. Worker、Redis 与其它外部系统

| 组件 | 约定 | 说明 |
| --- | --- | --- |
| Redis | `REDIS_URL`，默认 `redis://127.0.0.1:6379` | API 入队与 Worker 消费；`/health/ready` 探活 |
| 队列 | BullMQ 名 `judge-submissions` | `attempts=2`，指数退避 1500ms |
| 任务载荷 | `{ submissionId }` | Worker 读 `Submission`+`TestCase`，写回 `status`/`score`/`resultJson` |
| 并发 | Worker `concurrency: 4` | 可水平扩实例 |
| 运行器 | JS：`node`；Python：`python3` | Windows 无 `python3` 时 Python 题为 `ERROR`（ENV-D1-02） |
| 无用例 | 视为满分 `ACCEPTED` 100 | 见 `judge-worker/src/worker.ts` |
| LLM | OpenAI 兼容（DeepSeek 等） | 实验 AI、练习识题/辅导；无密钥则本地模板 |
| 文件 | `UPLOAD_DIR` 或 `backend/uploads` | API 与 Worker 必须一致 |

Worker **不是**第四个业务微服务，但是 lab-practice-service 的异步执行组件，独立进程/镜像。

## 7. 与网关路径的差异（给胡思琪）

草案写成 `/api/discussions/**`，实际讨论接口大量挂在 `/labs/.../discussions`、`/courses/.../discussions`。建议网关按前缀转发：

- `/api/lab-sets/**`、`/api/labs/**`、`/api/submissions/**`、`/api/testcases/**` → lab-practice-service  
- `/api/practice/**`、`/api/courses/:id/practice/**` → lab-practice-service  
- `/api/courses/:id/lab-sets/**`、`/api/courses/:id/labs`、`/api/courses/:id/discussions`、`/api/discussion-attachments/**` → lab-practice-service  
- `/api/wrong-book/**` → 待与闾玥确认（见 2.4）

前端现有调用已覆盖上述公开路径（实验管理、提交面板、练习页、讨论帖），公共 URL 尽量不变。

## 8. 评审意见（回复范文歆待补充项）
