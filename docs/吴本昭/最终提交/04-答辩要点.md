# 架构设计答辩要点（角色 B）

讲 3 分钟够用。不问细节方法名（那是详细设计）。

## 1. 为什么这样拆组件

按 **Controller → 领域服务 → DAO** 拆，对应三个目标服务，而不是按页面拆。

- 课程域：认证、课程、选课、公告、资料、管理、通知 → `course-service`
- 作业成绩：作业、成绩 → `homework-grade-service`
- 实验练习：实验、练习、讨论 + 评测 Worker → `lab-practice-service`

当前仓库仍是 **一个 Fastify + 独立 Worker**。总图按现状画；三个服务是拆分目标，不要说现在已经是三个进程。

## 2. 组件之间怎么通信

- **默认同步 HTTP**（JSON）。前端只调控制层，不直连数据库、不直连 Worker。
- **唯一异步主路径**：UC06 实验评测。API 向 Redis 队列 `judge-submissions` 投 `{ submissionId }`，Worker 再查库、跑代码、写回终态。
- **练习批改不入队**，在 API 进程内完成。
- 通知：同步写 `SiteNotification`；SSE 只是推送，可没有。
- 自动评测**不**发「已出分」通知，学生轮询提交状态。

## 3. 和详细设计的边界

概要设计停在组件和调用方向。类、字段、Prisma 关系、函数参数归闾玥对象级设计。不要在答辩里展开 `createCodeSubmission` 的参数列表。
