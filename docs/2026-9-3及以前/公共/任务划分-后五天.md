任务划分

当前服务划分是：

- `course-service`：UC01、UC02、UC03、UC04、UC10
- `homework-grade-service`：UC05、UC09
- `lab-practice-service`：UC06、UC07、UC08
- API Gateway、PostgreSQL、Redis、Judge Worker 不计入三个业务微服务。

# 一、最终责任划分

| 人员  | 核心角色                | 第一责任                                              |
| ----- | ----------------------- | ----------------------------------------------------- |
| **A** | 课程微服务负责人        | `course-service`                                      |
| **B** | 实验微服务负责人        | `lab-practice-service` + Judge Worker + 故障实验      |
| **C** | 作业微服务 / 集成负责人 | `homework-grade-service` + API Gateway + PPT/答辩统筹 |
| **D** | 云原生与 DevOps 负责人  | Docker + Kubernetes + CI/CD + HPA                     |
| **E** | 测试与质量负责人        | E2E + 性能对比 + 测试报告 + 追溯验收                  |

最重要的原则：

> **A/B/C 对自己的服务“从代码到测试到容器”负责；D 不替他们写完所有部署文件；E 不替他们写完所有测试。**

这样才能真正均衡。

# 九、D负责 CI/CD

这是 D 的核心验收项。

实现：

```text
Push
 ↓
拉代码
 ↓
安装依赖
 ↓
编译
 ↓
Unit Test
 ↓
Integration/API Test
 ↓
Docker Build
 ↓
Push Image
 ↓
Deploy Kubernetes
 ↓
Health Check
```

最关键：

```text
Test Failed
     ↓
STOP
```

不能继续：

```text
Build Image
Deploy
```

------

## D必须保存两个案例

### 成功案例

```text
push
→ test pass
→ image
→ deploy
→ health pass
```

### 失败案例

故意使测试失败：

```text
push
→ test fail
→ pipeline stop
→ 没有部署
```

最后答辩非常重要。

# 十八、最终一句话概括每个人

你们以后每天汇报甚至都可以直接按照这五句话：

> **A：保证 Course 服务独立、完整、可测试。**
> **B：保证 Lab + Judge 完整运行，并完成故障处理实验。**
> **C：保证 Homework、Gateway 和三服务调用关系跑通，并统筹答辩。**
> **D：保证所有服务能够自动构建、部署到 K8s 并完成 HPA。**
> **E：保证全部用例经过回归验证，并完成性能和实验数据证明。**

按照这个方案，出现问题也非常容易找责任人。例如 **Lab服务启动不了找B、Pod起不来找D、UC07 E2E失败先由E定位后交B修、Lab成绩接口没有提供找B、Homework没正确调用找C**。这样比“大家一起负责微服务、大家一起测试”要清楚得多。
