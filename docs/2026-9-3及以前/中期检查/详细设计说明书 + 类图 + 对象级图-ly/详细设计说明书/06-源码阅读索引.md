## 7. 关键设计发现

1. 项目实际架构是函数式组合，不应强行画 Java 式继承树。
2. `CourseContextValue` 大量使用 `any`，是前端类型安全最明显的技术债；应拆成 Course/Lab/Homework/Discussion/Material DTO。
3. `CourseProvider` 同时负责远程聚合、授权推导、表单状态和批改状态，职责偏重；可拆为查询 Hook 和领域 Provider。
4. 多个路由控制器同时承担输入校验、业务规则和持久化，微服务拆分前应把事务规则下沉到应用服务。
5. `loadGradebook` 位于路由文件内部，既供多接口复用又包含核心业务公式，建议抽为独立 `gradebook-service.ts`。
6. `WrongBookEntry` 被作业和练习两域共写，必须确定唯一所有者。
7. 管理员审计目前借用通知表，不是稳定审计模型。
8. API 与 Worker 共享数据库和上传目录，是实验评测必须保持的运行约束。
9. 前端路由有 student/teacher/admin 三套课程路径，公共页面组件已复用，但路由声明重复，后续可数据驱动生成。
10. 前端与后端都有相似标签匹配、作业状态等类型，拆分后应通过 OpenAPI 生成 DTO，避免手工漂移。
