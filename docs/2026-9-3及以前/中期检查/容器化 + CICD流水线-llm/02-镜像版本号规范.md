# 镜像版本号规范

## 一、仓库命名

镜像统一推送到 GitHub Container Registry：

```text
ghcr.io/<github-owner>/teaching-platform-api
ghcr.io/<github-owner>/teaching-platform-migrate
ghcr.io/<github-owner>/teaching-platform-web
ghcr.io/<github-owner>/teaching-platform-judge-worker
```

仓库 owner 在流水线中转换为小写，满足容器镜像名称要求。

## 二、不可变部署标签

每次构建都生成：

```text
sha-<40位 Git commit SHA>
```

例如：

```text
ghcr.io/vesperx24/teaching-platform-api:sha-0123456789abcdef0123456789abcdef01234567
```

API、迁移、Web、Worker 在同一次部署中必须使用完全相同的提交 SHA。该标签可从镜像反查代码，并可直接用于回滚。

## 三、辅助标签

工作流还可生成分支标签和 `v*` Git 标签，便于人工浏览发布记录；生产 Kubernetes 清单不得使用这些可移动标签，也不得使用 `latest`。

## 四、回滚原则

回滚时选择已验证成功的提交 SHA，同时更新 API、Web 和 Worker；若该版本包含数据库变更，应先确认 migration 的前向兼容性。Prisma migration 默认只向前执行，不自动执行破坏性回滚 SQL。
