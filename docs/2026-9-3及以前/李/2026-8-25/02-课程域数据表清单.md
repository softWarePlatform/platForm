# 课程域数据表清单

## 1. 范围与归属

课程域由后续 `course-service` 负责，覆盖课程、班级、选课、候补、选课时段、公告、已读、资料、收藏和通知。当前单体系统的模型定义位于 `backend/prisma/schema.prisma`。

本清单将表分为三类：

- 核心业务表：直接承载 UC01—UC04。
- 支撑表：为权限、日志、通知和选课阶段提供数据。
- 跨域关联：课程与作业、实验、练习之间的外键关系，拆分服务时需改为接口或标识引用。

## 2. 核心业务表

| Prisma 表 | 中文含义 | 关键字段 | 关键约束与索引 | 对应用例 |
| --- | --- | --- | --- | --- |
| `Course` | 课程 | `id`、`title`、`teacherId`、`published`、`courseCode`、`credits`、`capacity`、`courseNature`、`subjectCategory`、`offeringCollegeCode`、`semesterKey`、`scheduleSlotsJson` | `id` 主键；`courseCode` 唯一；删除教师时级联删除课程 | UC01、UC02、UC03、UC04 |
| `Class` | 教学班 | `id`、`name`、`courseId` | `courseId` 外键指向 `Course`；删除课程时级联删除 | UC01、UC02、UC04 |
| `Enrollment` | 正式选课 | `id`、`userId`、`courseId`、`classId` | `(userId, courseId)` 唯一，防止重复选课；删除课程或用户时级联；删除班级时 `classId` 置空 | UC01 |
| `EnrollmentWaitlist` | 候补队列 | `id`、`userId`、`courseId`、`createdAt`、`notifiedAt` | `(userId, courseId)` 唯一；按 `(courseId, createdAt)` 索引保证候补顺序查询 | UC01 |
| `CourseAnnouncement` | 课程公告 | `id`、`courseId`、`authorId`、`title`、`content`、`pinned`、`createdAt`、`updatedAt`、`editHistoryJson` | 按课程、置顶和创建时间建立索引；删除课程或作者时级联 | UC03 |
| `AnnouncementRead` | 公告已读记录 | `id`、`announcementId`、`userId`、`readAt` | `(announcementId, userId)` 唯一；删除公告或用户时级联 | UC03 |
| `AnnouncementMark` | 公告收藏/标记 | `id`、`announcementId`、`userId`、`createdAt` | `(announcementId, userId)` 唯一；按用户索引 | UC03 扩展功能 |
| `CourseMaterial` | 课程资料及版本 | `id`、`courseId`、`title`、`fileName`、`storedPath`、`mimeType`、`sizeBytes`、`uploadedById`、`folderPath`、`visibility`、`targetClassId`、`groupId`、`version`、`isCurrent`、`downloadCount` | 按课程、目录、置顶时间和版本组建立索引；删除课程时级联；删除目标班级时置空 | UC04 |
| `MaterialFavorite` | 资料收藏 | `id`、`userId`、`materialId`、`createdAt` | `(userId, materialId)` 唯一；删除用户或资料时级联 | UC04 |

## 3. 支撑表

| Prisma 表 | 中文含义 | 课程域用途 | 关键约束 |
| --- | --- | --- | --- |
| `User` | 用户 | 教师、学生和管理员主体；关联授课、选课、公告作者、资料上传者和收藏者 | `email` 唯一；角色为 `STUDENT`、`TEACHER`、`ADMIN` |
| `EnrollmentLog` | 选课操作日志 | 记录选课、退课、候补、管理员操作、课表确认和课程创建 | 按用户/课程与创建时间索引；`action` 使用 PostgreSQL 枚举 `EnrollmentLogAction` |
| `EnrollmentPeriod` | 选课阶段 | 保存当前学期的预选、正选、补退选或关闭阶段及时间窗 | `semesterKey` 唯一 |
| `TimetableConfirmation` | 课表确认 | 选课结束后记录学生对学期课表的确认时间 | `(userId, semesterKey)` 唯一 |
| `SiteNotification` | 站内通知 | 公告发布、资料上传和选退课时向相关用户发送通知 | 按 `(userId, readAt)` 和 `(userId, createdAt)` 索引；公告或资料删除后关联字段置空 |

## 4. 表关系

| 主表 | 关系 | 从表 | 说明 |
| --- | --- | --- | --- |
| `User` | 1:N | `Course` | 一个教师可创建多门课程 |
| `Course` | 1:N | `Class` | 一门课程可有多个教学班 |
| `User` + `Course` | N:M | `Enrollment` | 学生与课程的正式选课关系 |
| `User` + `Course` | N:M | `EnrollmentWaitlist` | 学生与已满课程的候补关系 |
| `Course` | 1:N | `CourseAnnouncement` | 一门课程有多条公告 |
| `CourseAnnouncement` + `User` | N:M | `AnnouncementRead` | 每个学生对每条公告最多一条已读记录 |
| `CourseAnnouncement` + `User` | N:M | `AnnouncementMark` | 每个用户对每条公告最多一条标记记录 |
| `Course` | 1:N | `CourseMaterial` | 一门课程有多份资料和历史版本 |
| `Class` | 1:N | `CourseMaterial` | `visibility=CLASS` 时限定目标班级 |
| `CourseMaterial` + `User` | N:M | `MaterialFavorite` | 每个用户对每份资料最多一条收藏记录 |
| `User` | 1:N | `SiteNotification` | 用户拥有多条通知 |
| `CourseAnnouncement` / `CourseMaterial` | 1:N | `SiteNotification` | 公告或资料发布后产生通知 |

## 5. UC01—UC04 的写入路径

| 操作 | 主要写入表 | 联动表 |
| --- | --- | --- |
| 创建/配置/发布课程 | `Course` | `EnrollmentLog`（课程创建日志） |
| 学生选课 | `Enrollment` | `EnrollmentLog`、`SiteNotification` |
| 学生退课 | 删除 `Enrollment` | `EnrollmentLog`、`SiteNotification`；可能触发候补晋升 |
| 加入/退出候补 | `EnrollmentWaitlist` | `EnrollmentLog` |
| 确认课表 | `TimetableConfirmation` | `EnrollmentLog` |
| 教师发布公告 | `CourseAnnouncement` | `SiteNotification` |
| 学生阅读公告 | `AnnouncementRead` | 同步更新相关 `SiteNotification.readAt` |
| 教师上传资料 | `CourseMaterial` | 文件存储、`SiteNotification` |
| 学生收藏资料 | `MaterialFavorite` | 无 |
| 学生下载资料 | 更新 `CourseMaterial.downloadCount`、`lastDownloadAt` | 文件存储 |

## 7. 数据一致性与拆分注意事项

1. `Course.courseCode`、`Enrollment(userId, courseId)`、`EnrollmentWaitlist(userId, courseId)`、`AnnouncementRead(announcementId, userId)` 和 `MaterialFavorite(userId, materialId)` 的唯一约束必须保留。
2. 课程删除会级联删除大量课程域数据；微服务拆分后不应允许其他服务直接级联操作课程库。
3. `SiteNotification` 当前同时服务多个业务域。拆分时应明确由课程服务统一管理，或改为事件驱动的独立通知能力。
4. `scheduleSlotsJson` 当前以 JSON 文本保存课表时段；如需数据库级冲突查询，后续可规范化为独立课表时段表。
5. `CourseMaterial.storedPath` 只保存文件路径，数据库清理必须与文件存储清理配套。
6. 当前数据库的 `EnrollmentLogAction` 已通过迁移补充 `COURSE_CREATE`，课程与创建日志使用同一事务写入，详见 [`03-缺陷记录.md`](./03-缺陷记录.md)。

## 8. 跨服务边界

`Course` 目前还被实验、作业、练习和讨论模型引用。拆分为 `course-service` 后建议遵循：

- 课程服务独占 `Course`、`Class`、`Enrollment`、公告和资料表的直接读写。
- 作业成绩服务、实验练习服务仅保存 `courseId` 业务标识，通过课程服务接口校验课程、教师和选课关系。
- 删除课程采用显式业务流程或领域事件，避免跨数据库外键级联。
- 对外提供课程基本信息、教师权限、学生是否选课、课程名单等稳定接口。
