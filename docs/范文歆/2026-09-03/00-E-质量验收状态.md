仓库新增 `scripts/qa/performance-benchmark.mjs`。它强制 2 - 3 个接口、至少 3 轮，逐请求保留原始状态码/耗时，并输出 QPS、Avg、P95、错误率。压力配置不得提交 Token；配置应保存在被忽略的 `test-results/`，并同时归档每轮 `kubectl top pods -n teaching-platform` 的原始输出作为 CPU/内存证据。

恢复环境后的统一执行方法如下。两种版本必须使用同一份 `targets`、相同 `concurrency`、相同 `requestsPerTarget`、同一数据集标识；只允许改变 `environment` 与 `baseUrl`。目标接口选择 Dashboard、作业/成绩、实验查询三项中的任意两至三项。

```powershell
# 配置文件保存在被忽略目录，认证头不会写入 Git。
$config = @{
  environment = "monolith" # 第二轮改为 microservices
  baseUrl = "http://<host>"
  datasetId = "seed-<same-id>"
  sameMachineEvidence = "<host-name-and-run-date>"
  runs = 3
  concurrency = 50
  requestsPerTarget = 500
  requestTimeoutMs = 10000
  targets = @(
    @{ name = "dashboard"; path = "/api/dashboard/me"; headers = @{ authorization = "Bearer <test-token>" } },
    @{ name = "homework"; path = "/api/homework/mine"; headers = @{ authorization = "Bearer <test-token>" } },
    @{ name = "lab"; path = "/api/lab-sets/mine/overview"; headers = @{ authorization = "Bearer <test-token>" } }
  )
}
$config | ConvertTo-Json -Depth 5 | Set-Content -Encoding utf8 test-results/perf-config.json
npm run qa:perf -- --config test-results/perf-config.json --output test-results/perf-monolith.json

# 微服务使用相同 config，仅修改 environment/baseUrl 后再执行一次。
kubectl top pods -n teaching-platform | Tee-Object test-results/perf-microservices-pods.txt
kubectl get hpa -n teaching-platform | Tee-Object test-results/perf-microservices-hpa.txt
```

HPA 实验须分别在压测前、负载峰值（Pod 扩容后）和停止压测并稳定后采集上述 Pod/HPA 输出；每个时点关联同轮原始 JSON，避免仅保留截图。
