# E - 单体与微服务性能对比报告

- 日期：2026-09-03
- 环境：同一 Windows 主机、Docker Desktop Kubernetes、通过 localhost `kubectl port-forward` 访问。
- 压测脚本：`scripts/qa/performance-benchmark.mjs`
- 条件：每端 3 轮；并发 10；每个目标每轮 30 个请求；超时 10 秒。

## 可比性控制

测试没有运行任何清库或 destructive seed。通过 `scripts/qa/create-performance-fixture.mjs` 在两端分别创建等价的隔离数据：一名教师、一名学生、已发布课程、选课关系、一份已发布作业、一个实验集和一道实验题。资源名称和 ID 不同是独立数据库的正常现象，角色、数据数量、发布状态和访问路径一致。两个 fixture manifest 分别保存为：

- `test-results/perf-fixture-monolith.json`
- `test-results/perf-fixture-microservices.json`

单体的 `MONOLITH_HOMEWORK_ROUTES=1` 仅在创建数据和压测期间启用，压测结束后已移除该环境变量并完成 API rollout；原部署语义已恢复。

## 结果（3 轮中位数）

| 接口 | 单体 QPS | 微服务 QPS | 单体 Avg / P95 | 微服务 Avg / P95 | 错误率 |
| --- | ---: | ---: | --- | --- | --- |
| `GET /dashboard/me` | 128.06 | 679.50 | 193.56 / 230.56 ms | 16.36 / 38.11 ms | 0 / 0 |
| `GET /homework/mine` | 135.29 | 901.44 | 204.96 / 211.03 ms | 18.60 / 27.85 ms | 0 / 0 |
| `GET /lab-sets/mine/overview` | 174.02 | 1493.28 | 147.21 / 169.14 ms | 16.71 / 17.42 ms | 0 / 0 |

本次本地、低并发条件下，微服务三类接口的中位 QPS 更高、Avg/P95 更低，且两端均无请求错误。首轮冷启动/JIT 波动已完整保留在原始记录中，因此结论使用中位数而非只展示最优轮次。
