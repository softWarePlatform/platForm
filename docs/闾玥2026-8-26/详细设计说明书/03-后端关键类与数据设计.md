# 03 后端关键类与数据设计

## 1. 类型组织方式

后端没有自定义业务 `class`。控制器以 `FastifyPluginAsync` 函数实现，领域逻辑以纯函数/异步函数实现，实体由 Prisma 生成类和类型。其依赖方向为：

```text
Route Plugin → Domain Function → Prisma Client → PostgreSQL
             → Queue / File / LLM
```

## 6. Worker 与运行器

### `JudgeWorker`

- 属性：`queueName=judge-submissions`、Redis connection、Prisma Client、`concurrency=4`、默认超时。
- 方法等价物：BullMQ processor 回调、`mapLanguage`、`failed` 事件处理。
- 输入：`{submissionId}`。
- 行为：标记 JUDGING → 加载提交/题目/用例 → 读代码或文件 → 顺序运行用例 → 按权重计分 → 回写终态。

### `CodeRunner`

- 类型：`RunnerLanguage = javascript | python`。
- 方法：`runCode(opts)`、`normalizeOutput(text)`。
- 属性：临时目录、扩展名、命令（node/python3）、stdin、timeout。
- 资源生命周期：创建临时目录 → 写源码 → spawn → 输入 → 等待/超时杀进程 → 删除目录。

## 7. 继承与接口关系结论

- 无业务类继承树，无抽象基类。
- 路由模块以结构类型满足 `FastifyPluginAsync`。
- React 之外的后端 DTO 使用 TypeScript `type`，通过泛型、交叉类型和 `Pick/Omit/ReturnType` 复用结构。
- Prisma 关系是实体关联，不是继承。
- Worker 通过实例化第三方 `Worker` 类并传入处理函数实现组合，不继承 BullMQ Worker。
