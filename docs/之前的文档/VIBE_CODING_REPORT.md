# Vibe Coding 开发报告

## 一、项目概述

本项目是一套面向在线教学场景的综合平台，围绕学生、教师、管理员三类角色展开设计，主要功能包括课程管理、选课、公告、资料、实验、作业、成绩、消息通知和后台管理等。

在开发过程中，团队采用了 Vibe Coding 的开发方式。整体思路是：项目需求、功能边界、业务流程和最终验收由团队成员负责；AI 工具主要参与代码定位、重复性代码生成、局部功能实现建议、错误排查和文档整理。项目并非完全由 AI 自动完成，而是将整体任务拆分后，部分由团队主导完成，部分借助 AI 提高效率。

## 二、整体任务拆分

| 三端路由设计 | 区分学生端、教师端、管理员端课程入口 | 团队设计，AI 辅助代码调整 |
| 课程模块 | 课程列表、课程详情、课程资料、课程管理 | 团队主导，AI 辅助优化 |

| 实验与练习模块 | 实验入口、实验提交、练习功能、AI 辅导入口 | 团队完成主要逻辑，AI 辅助局部整理 |

## 三、团队主要完成的工作

### 3.1 项目需求与业务流程确定

团队首先根据在线教学平台的使用场景，确定了学生、教师、管理员三类角色的功能范围。

团队完成的主要工作包括：

- 确定学生端需要支持课程学习、作业提交、实验完成、成绩查看和消息接收。
- 确定教师端需要支持课程管理、作业布置、作业批改、实验管理和成绩发布。
- 确定管理员端需要支持用户管理、班级目录、日志查看和课程作业完成情况统计。
- 明确学生操作后教师和管理员应收到反馈，教师操作后学生和管理员也应收到反馈。
- 明确作业重做申请需要形成完整闭环。

这些内容属于项目业务设计部分，主要由团队根据课程项目要求和实际演示需要完成。

### 3.2 三端功能边界设计

项目中学生、教师、管理员都会进入课程页面，但三类用户的操作权限不同。团队决定将课程入口按身份区分，避免不同身份共用同一路径后产生功能混淆。

团队确定的路由规则包括：

- 学生课程入口：`/student/courses/:courseId`
- 教师课程入口：`/teacher/courses/:courseId`
- 管理员课程入口：`/admin/courses/:courseId`

同时，团队保留旧路径兼容跳转，保证已有链接不会直接失效。

### 3.3 作业业务流程设计

作业模块的业务流程由团队重点梳理，包括：

1. 教师布置作业。
2. 学生查看作业要求。
3. 学生提交作业。
4. 教师查看提交记录。
5. 教师批改并填写反馈。
6. 教师发布成绩。
7. 学生查看成绩和反馈。
8. 学生在允许条件下申请重做。
9. 教师处理重做申请。
10. 管理员查看课程作业完成情况。

团队主要负责确认这些流程是否符合教学逻辑，以及不同角色在每一步应具备哪些权限。

### 3.4 管理员功能规划

管理员端是本项目的重要组成部分。团队确定管理员不仅需要用户和日志管理，还需要从平台角度查看课程运行情况。

管理员端主要规划内容包括：

- 用户管理。
- 班级目录。
- 管理员操作日志。
- 指定用户日志。
- 课程作业完成情况。
- 课程作业日志记录。

其中“管理员查看学生作业完成情况”和“选择课程查看日志记录”是本阶段重点新增功能。

### 3.5 测试与最终验收

开发完成后，团队负责执行验证命令并检查运行结果。

主要验证内容包括：

- 前端类型检查。
- 后端类型检查。
- 前端生产构建。
- 后端生产构建。
- 页面跳转路径检查。
- 学生、教师、管理员三端入口检查。
- 作业提交、批改、重做申请流程检查。
- 消息跳转结果检查。

最终是否接受修改，由团队结合运行结果和功能表现进行确认。

## 四、AI 主要辅助完成的工作

### 4.1 代码结构梳理

项目文件较多，前后端涉及课程、作业、通知、成绩、管理员后台等多个模块。AI 辅助完成了代码定位工作，例如：

- 查找课程路由定义位置。
- 查找作业提交和批改接口。
- 查找消息通知接口。
- 查找学生端“我的作业”页面。
- 查找教师端作业批改组件。
- 查找管理员路由和页面结构。

这部分主要提高了定位效率，减少了人工在大量文件中逐个查找的时间。

### 4.2 局部代码生成与修改建议

在团队确认功能目标后，AI 辅助生成或修改了部分代码。

主要包括：

- 课程路径辅助函数。
- 消息跳转解析逻辑。
- 管理员作业完成情况接口。
- 管理员作业完成情况页面。
- 学生已完成作业卡片跳转。
- 教师端重做申请展示区域。
- 作业列表卡片样式。
- 学生作业提交面板样式。
- 教师批改面板样式。

这些代码并不是直接脱离项目生成，而是在已有代码结构基础上进行局部调整。

### 4.3 报错分析与修复辅助

在开发过程中，类型检查和构建会暴露一些问题。AI 辅助分析了部分报错原因，例如：

- Prisma 查询字段不存在。
- 前端组件缺少导入。
- 路由跳转路径不匹配。
- TypeScript 类型字段缺失。
- CSS class 引用不一致。
- 后端构建写入权限受限。

AI 提供了问题原因和修复方向，团队再根据实际情况进行确认和处理。

### 4.4 文档初稿整理

项目文档部分也使用了 AI 辅助整理，包括：

- 用户手册。
- Vibe Coding 开发报告。
- 人员分工表。
- 功能说明内容。

团队提供文档方向和需要包含的模块，AI 辅助将内容整理为 Markdown 格式，最后再由团队确认是否适合提交。

## 五、按功能模块划分的完成情况

### 5.1 课程模块

课程模块主要包括课程列表、课程详情、课程资料、课程管理和三端课程入口。

团队完成：

- 确定课程模块在学生、教师、管理员三端中的功能边界。
- 确定三端课程路径的命名方式。
- 判断旧路径是否需要兼容。

AI 辅助完成：

- 查找前端路由和课程相关组件。
- 辅助替换部分旧课程路径。
- 整理路径生成工具函数。

### 5.2 作业模块

作业模块包括教师布置作业、学生提交作业、教师批改、成绩发布、重做申请和作业状态展示。

团队完成：

- 确定作业完整业务流程。
- 确定学生已完成作业仍需可查看详情。
- 确定教师端必须能看到学生重做申请。
- 确定管理员需要查看课程作业完成情况。

AI 辅助完成：

- 辅助修改作业列表页面。
- 辅助修复“已完成作业无法点击”的问题。
- 辅助生成教师端重做申请展示逻辑。
- 辅助调整作业卡片和提交面板样式。
- 辅助完善作业状态显示。

### 5.3 消息通知模块

消息通知模块负责展示站内消息，并根据消息类型跳转到对应页面。

团队完成：

- 确定消息跳转规则。
- 确定不同身份点击同一类消息时应进入不同端口。
- 确定作业、公告、资料、实验、练习等消息类型的目标页面。

AI 辅助完成：

- 辅助补充后端通知接口字段。
- 辅助编写前端消息跳转解析逻辑。
- 辅助兼容旧 `/courses/...` 链接。
- 辅助整理消息类型标签。

### 5.4 管理员模块

管理员模块包括用户管理、班级目录、管理员日志、用户日志和作业完成情况。

团队完成：

- 确定管理员后台需要查看课程层面的作业完成情况。
- 确定管理员应通过选择课程查看对应日志。
- 确定统计页面需要展示学生、作业、完成率和日志。

AI 辅助完成：

- 辅助新增管理员作业完成情况接口。
- 辅助新增管理员作业完成情况页面。
- 辅助生成作业状态矩阵。
- 辅助补充管理员导航入口。
- 辅助调整统计表格样式。

### 5.5 实验与练习模块

实验与练习模块主要包括实验列表、实验提交、实验完成情况和课程练习。

团队完成：

- 保留原有实验和练习功能结构。
- 确认实验、练习消息跳转应进入对应课程页面。
- 确认三端路由调整不能影响实验原有入口。

AI 辅助完成：

- 辅助检查实验相关旧路径。
- 辅助调整部分入口跳转。
- 辅助确认构建过程中没有破坏实验和练习模块。

### 5.6 前端 UI 与交互

前端体验优化主要集中在作业、消息和管理员统计页面。

团队完成：

- 确认页面需要更清晰地区分操作入口。
- 确认作业卡片、提交区、批改区需要优化。
- 确认管理员统计页面需要便于横向查看。

AI 辅助完成：

- 辅助补充作业卡片 CSS。
- 辅助补充提交面板 CSS。
- 辅助补充批改卡片 CSS。
- 辅助补充消息正文摘要展示。
- 辅助补充管理员状态标签样式。

### 5.7 测试与文档

测试和文档是项目提交的重要部分。

团队完成：

- 运行检查命令。
- 查看构建结果。
- 判断功能是否达到预期。
- 确认文档内容是否符合提交要求。

AI 辅助完成：

- 辅助整理验证命令。
- 辅助根据开发内容生成用户手册。
- 辅助生成 Vibe Coding 报告。
- 辅助整理人员分工表。

## 十、总结

本项目采用 Vibe Coding 方式进行开发，但整体过程并不是完全依赖 AI 自动生成。团队主要负责需求判断、业务流程设计、功能边界确认和最终验收；AI 主要负责代码定位、局部实现辅助、错误分析和文档整理。

通过这种分工方式，项目在保证人工参与和质量控制的基础上，提高了开发效率。最终系统在三端角色区分、作业流程、消息跳转、管理员统计和文档完善方面都取得了较明显的改进，能够更好地支持在线教学平台的使用和项目提交。
