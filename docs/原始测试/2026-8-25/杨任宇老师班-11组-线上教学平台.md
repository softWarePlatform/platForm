## 2. 编制原则

本清单以当前仓库已经实现的业务流程、接口和测试资料为依据。一个业务用例是由一类用户或外部系统触发，为完成明确业务目标，从开始到产生可验证结果的一段完整流程。

以下内容不单独列为业务用例：

- 登录、注册、查看单个页面等支撑步骤；
- 单个按钮、接口、数据库操作或普通增删改查；
- 健康检查、容器构建、流水线运行等工程支撑能力；
- AI 模型调用本身。AI 提示或本地模板降级作为相应用例的备选流程处理。

## 5. 详细用例说明

### UC01 完成选课、退课或候补并同步课表

| 字段 | 内容 |
| --- | --- |
| 主要参与者 | 学生 |
| 次要参与者 | 管理员、教师 |
| 触发条件 | 学生希望在当前学期选择课程、退出课程或加入候补队列 |
| 前置条件 | 学生已登录；课程已发布；当前处于允许相应操作的选课阶段 |
| 后置条件 | 学生的选课或候补记录、课程容量、课程成员名单和个人课表保持一致 |

主成功流程：

1. 学生进入选课目录，系统显示当前学期和选课阶段。
2. 学生按课程性质、类别、学院、课程代码、教师或时间等条件筛选课程。
3. 学生查看课程容量、上课时间和本人当前选课状态。
4. 学生发起选课，系统检查选课窗口、重复选课、容量和时间冲突等规则。
5. 校验通过后，系统创建选课记录并占用课程名额。
6. 系统在学生“我的课程”和个人课表中显示该课程，并在教师名单中显示该学生。

备选或异常流程：

- 课程已满时，学生可按系统规则进入候补队列；出现空位后按候补顺序处理。
- 学生退课后，系统释放名额并从个人课表移除课程；必要时触发候补递补。
- 非选课时间、重复选课、课程未发布或发生时间冲突时，系统拒绝操作并返回明确原因。
- 管理员可在权限范围内调整选课阶段，教师可查看课程学生名单。

可验证结果：

- 选课接口返回成功后，课程成员、容量和 `/dashboard/me` 课表结果一致。
- 退课后名额恢复，学生课表不再出现该课程。
- 满课、非选课窗口等异常路径不会错误创建正式选课记录。

实现与测试索引：`backend/src/routes/enrollment.ts`、`backend/src/routes/dashboard.ts`、`backend/src/routes/courses.ts`；`TC-ENROLL-001` 至 `TC-ENROLL-006`、`TC-DASH-001` 至 `TC-DASH-004`。

### UC02 创建、配置并发布课程

| 字段 | 内容 |
| --- | --- |
| 主要参与者 | 教师 |
| 次要参与者 | 管理员、学生 |
| 触发条件 | 教师需要为新学期建立一门课程并向学生开放 |
| 前置条件 | 教师已登录并具有课程管理权限 |
| 后置条件 | 课程及其代码、容量、分类、时间地点和发布状态被持久化 |

主成功流程：

1. 教师填写课程名称、课程代码、描述、分类和学期信息。
2. 教师配置课程性质、开课学院、容量、上课时间和地点。
3. 系统校验必填字段和课程代码唯一性后创建未发布课程。
4. 教师检查课程配置并将课程发布。
5. 系统将已发布课程加入学生可浏览的课程目录，同时保留教师管理入口。

备选或异常流程：

- 课程代码重复或字段不合法时，系统拒绝创建并提示冲突字段。
- 教师可修改课程配置、课表时段或容量；无权限用户不能修改。
- 课程保持未发布或被取消发布时，普通学生不能从公开课程列表访问。
- 删除存在关联数据的课程时，应按系统约束拒绝或进行受控清理，避免产生孤立数据。

可验证结果：

- 教师课程列表能查询到新课程及完整配置。
- 发布后学生课程目录可见；未发布时学生访问得到拒绝或不存在结果。
- 相同课程代码不能被重复创建。

实现与测试索引：`backend/src/routes/courses.ts`；`TC-COURSE-001` 至 `TC-COURSE-005`。

### UC03 发布并阅读课程公告

| 字段 | 内容 |
| --- | --- |
| 主要参与者 | 教师、学生 |
| 次要参与者 | 通知服务 |
| 触发条件 | 教师需要向课程成员发布教学通知 |
| 前置条件 | 教师管理该课程；学生已选该课程 |
| 后置条件 | 公告被保存并对课程成员可见，学生阅读状态可追踪 |

主成功流程：

1. 教师在课程中填写公告标题、正文和置顶状态并发布。
2. 系统保存公告，并按置顶状态和发布时间更新公告列表。
3. 系统为课程成员生成站内通知和未读记录。
4. 学生从课程公告列表或通知入口打开公告详情。
5. 系统显示完整公告并记录该学生已读，未读数量随之更新。

备选或异常流程：

- 教师可编辑公告；学生再次打开时看到更新后的内容。
- 教师删除公告后，公告不再出现在有效列表中，旧通知跳转不得泄露无效内容。
- 非课程成员不能读取公告，无课程管理权限的用户不能发布、编辑或删除公告。
- 通知生成失败时，公告主体仍应保持一致，并留下可诊断的失败信息。

可验证结果：

- 教师发布后学生公告列表出现对应内容。
- 学生打开详情后公告阅读记录存在，未读数减少。
- 编辑、删除和权限异常路径的公告状态与返回结果一致。

实现与测试索引：`backend/src/routes/announcements.ts`、`backend/src/routes/notifications.ts`；`TC-ANN-001` 至 `TC-ANN-003`、`TC-NOTIFY-001` 至 `TC-NOTIFY-002`。

### UC04 发布并获取课程资料

| 字段 | 内容 |
| --- | --- |
| 主要参与者 | 教师、学生 |
| 次要参与者 | 文件存储模块 |
| 触发条件 | 教师需要发布学习文件，或学生需要浏览、收藏和下载资料 |
| 前置条件 | 教师管理该课程；学生具有课程访问资格；上传文件符合服务端限制 |
| 后置条件 | 资料元数据与物理文件一致，授权用户可以稳定访问 |

主成功流程：

1. 教师选择课程目录并上传资料文件，填写名称和相关描述。
2. 系统校验文件大小和请求参数，保存文件及资料元数据。
3. 学生进入课程资料列表，查看文件名、上传者和上传时间。
4. 学生浏览或下载资料，系统返回正确文件内容。
5. 学生可收藏重要资料，并在个人收藏入口再次访问。

备选或异常流程：

- 教师可更新资料信息、移动目录或删除本人有权管理的资料。
- 文件过大、参数不完整或存储失败时，系统拒绝上传且不保留无效元数据。
- 非课程成员或无管理权限用户不能访问受限资料或执行管理操作。
- 文件已删除或磁盘文件缺失时，下载请求返回明确错误而不是空文件。

可验证结果：

- 上传成功后资料列表包含正确元数据，下载内容与上传文件一致。
- 收藏状态能够保存和取消。
- 超限文件被拒绝，数据库与文件目录中不产生残留记录。

实现与测试索引：`backend/src/routes/course-materials.ts`；`TC-MAT-001` 至 `TC-MAT-003`。

### UC05 完成作业发布、提交、批改和重做

| 字段 | 内容 |
| --- | --- |
| 主要参与者 | 教师、学生 |
| 次要参与者 | 通知服务、AI 服务或本地降级模块 |
| 触发条件 | 教师布置作业，学生完成并提交，教师进行批改 |
| 前置条件 | 课程存在且双方具有课程权限；作业时间和提交规则已配置 |
| 后置条件 | 作业、提交版本、批改结果、迟交状态和重做记录形成完整闭环 |

主成功流程：

1. 教师填写作业标题、要求、附件、截止时间、迟交和重做规则并发布。
2. 学生在课程或“我的作业”中查看作业要求。
3. 学生保存草稿，确认内容后正式提交。
4. 系统锁定正式提交内容并记录提交时间及当前状态。
5. 教师打开待批改列表，填写分数、评语并发布批改结果。
6. 学生查看成绩、评语和知识点分析结果。

备选或异常流程：

- 截止时间后允许迟交时，系统标注迟交并应用扣分规则；不允许迟交时拒绝提交。
- 教师可将提交打回并填写原因；规则允许时学生申请或执行重做并再次提交。
- 学生在正式提交前可更新或删除草稿，正式提交后按规则限制修改。
- 越权访问、无效作业、非法分数或超过重做次数时，系统拒绝操作。
- 外部 AI 不可用时，知识点分析使用本地模板降级，不影响作业成绩主流程。

可验证结果：

- 学生提交后状态、内容和提交时间正确，教师能够读取同一份提交。
- 发布成绩后教师端与学生端的分数和评语一致。
- 迟交、打回和重做次数按作业配置执行，并保留历史记录。

实现与测试索引：`backend/src/routes/homework.ts`、`backend/src/routes/homework-student.ts`；`TC-HW-001` 至 `TC-HW-006`。

### UC06 完成实验发布、提交和自动评测

| 字段 | 内容 |
| --- | --- |
| 主要参与者 | 教师、学生、评测 Worker |
| 次要参与者 | Redis 队列、通知服务、AI 服务或本地降级模块 |
| 触发条件 | 教师发布编程实验，学生提交代码请求评测 |
| 前置条件 | 实验集和题目已发布；测试用例及时间窗口已配置；数据库和 Redis 可用 |
| 后置条件 | 提交获得终态、分数和可展示反馈，实验进度与成绩同步 |

主成功流程：

1. 教师创建实验集，设置开始时间、截止时间、补交和打回规则。
2. 教师创建实验题目，配置语言、资源限制以及公开和隐藏测试用例。
3. 学生进入实验题目，阅读说明并提交代码。
4. API 保存提交并向 Redis 队列写入评测任务，提交状态变为等待评测。
5. 评测 Worker 获取任务，在受限环境运行代码并逐用例判定结果。
6. Worker 写回得分、结果分类和用例详情，学生端显示最终状态。
7. 教师查看班级提交和统计结果，必要时确认完成情况。

备选或异常流程：

- 实验未开始、已截止且不允许补交时，系统拒绝提交。
- 编译错误、答案错误、运行超时或运行时错误时，系统返回相应分类和允许公开的诊断信息。
- 隐藏测试用例只显示通过状态，不向学生泄露输入、期望输出或完整错误细节。
- Worker 暂时不可用时提交保持等待状态；Worker 恢复后继续消费，不能伪造成功结果。
- 教师打回提交后学生看到原因，并在规则允许时重新提交或补交。
- AI 分析不可用时返回安全的模板提示，且不得泄露隐藏测试用例。

可验证结果：

- 正确代码最终为通过状态，错误代码得到与实际执行一致的失败分类。
- 提交状态按照“等待评测-评测中-终态”变化，得分等于通过用例分值汇总。
- 学生端不出现隐藏用例输入输出，教师端能够查看授权范围内的完整统计。

实现与测试索引：`backend/src/routes/lab-sets.ts`、`backend/src/routes/labs.ts`、`judge-worker/src/worker.ts`；`TC-LAB-001` 至 `TC-LAB-007`。

### UC07 完成练习组卷、答题和错题反馈

| 字段 | 内容 |
| --- | --- |
| 主要参与者 | 学生 |
| 次要参与者 | 教师、AI 服务或本地降级模块 |
| 触发条件 | 学生希望按知识点、难度或错题情况开展一次练习 |
| 前置条件 | 学生已登录并具有课程访问资格；课程题库存在可用题目 |
| 后置条件 | 练习会话、每题答案、得分、错题和学习反馈被保存 |

主成功流程：

1. 学生选择智能组卷、知识点练习、错题练习或自定义练习。
2. 系统按题量、难度和标签筛选题库并创建练习会话。
3. 学生逐题作答，系统保存当前答案和进度。
4. 学生提交整份练习，系统对客观题和可自动执行题目进行判分。
5. 系统返回总分、逐题结果和解析，并把错误题目纳入后续错题练习范围。
6. 学生可请求分步提示、相似题或提交题目质量反馈。

备选或异常流程：

- 筛选条件下题目不足时，系统返回可理解的提示或按规则缩小题量，不能创建空会话。
- 未完成全部题目时，系统按产品规则提示确认或保留未答状态。
- AI 服务不可用时返回本地模板提示，不影响答案保存和客观判分。
- 教师可处理学生反馈、修改题目并确认答案；无教师权限的用户不能管理题库。

可验证结果：

- 会话中的题目符合选择条件，提交后的总分与逐题结果一致。
- 错题练习能够抽取历史错误题目，题目反馈可在教师端查询和处理。
- AI 或模板提示不直接篡改正式答案和成绩。

实现与测试索引：`backend/src/routes/practice.ts`；`TC-PRACTICE-001` 至 `TC-PRACTICE-006`。

### UC08 参与实验讨论并接收提醒

| 字段 | 内容 |
| --- | --- |
| 主要参与者 | 学生、教师 |
| 次要参与者 | 通知服务 |
| 触发条件 | 课程成员需要围绕课程、实验集或实验题目提出问题并交流 |
| 前置条件 | 用户已登录且具有对应课程或实验访问权限 |
| 后置条件 | 帖子、回复、提及关系、解决状态和通知记录保持一致 |

主成功流程：

1. 学生进入课程或实验讨论区，填写主题和正文并发布帖子。
2. 系统保存帖子并在讨论列表中展示。
3. 教师或其他课程成员打开帖子并发表回复。
4. 用户在内容中提及课程成员时，系统为被提及者生成通知。
5. 被提及者从通知入口打开对应讨论，系统更新通知已读状态。
6. 问题解决后，发帖者或有权限的教师将帖子标记为已解决。

备选或异常流程：

- 用户可在权限范围内编辑或删除自己的内容，教师可处理不当内容。
- 非课程成员不能读取或发布讨论，越权编辑和删除请求被拒绝。
- 附件或提及对象无效时，系统拒绝相应部分并返回明确提示。
- 通知暂时不可用时，讨论正文不能丢失，相关失败应可诊断或重试。

可验证结果：

- 帖子和回复按正确的课程、实验集或实验题目归档。
- 提及后目标用户通知列表和未读数增加，打开后状态更新。
- 已解决、编辑和删除状态在讨论列表与详情中一致。

实现与测试索引：`backend/src/routes/discussions.ts`、`backend/src/routes/notifications.ts`；`TC-LAB-006`、`TC-NOTIFY-001` 至 `TC-NOTIFY-002`。

### UC09 配置并查看课程综合成绩

| 字段 | 内容 |
| --- | --- |
| 主要参与者 | 教师、学生 |
| 次要参与者 | 作业模块、实验模块 |
| 触发条件 | 教师需要汇总课程成绩，或学生需要查看个人成绩 |
| 前置条件 | 课程存在；学生已选课；相关作业和实验已经产生可计分结果 |
| 后置条件 | 成绩权重、分项成绩和综合成绩被保存并对授权用户可见 |

主成功流程：

1. 教师进入课程成绩管理，查看学生名单及作业、实验分项成绩。
2. 教师配置各成绩模块权重，系统校验权重规则。
3. 系统根据已发布的分项成绩计算每名学生的综合成绩。
4. 教师查看班级成绩册、统计结果，并按需要导出成绩。
5. 学生进入个人成绩页面，查看各分项得分、权重和综合结果。

备选或异常流程：

- 权重总和或单项范围不合法时，系统拒绝保存并保留原配置。
- 尚未批改或未发布的成绩按系统规则显示为空或不计入，不能伪造为零分。
- 教师修改权重后系统重新计算，并保持成绩册和学生端一致。
- 学生只能查看本人结果，教师只能管理其有权访问的课程。

可验证结果：

- 综合成绩与分项成绩及权重计算结果一致。
- 教师成绩册和学生个人成绩显示同一结果。
- 非法权重和越权查询被拒绝，导出内容与页面数据一致。

实现与测试索引：`backend/src/routes/grades.ts`、`backend/src/routes/homework.ts`、`backend/src/routes/labs.ts`；`TC-GRADE-001` 至 `TC-GRADE-003`。

### UC10 管理选课阶段、用户和操作记录

| 字段 | 内容 |
| --- | --- |
| 主要参与者 | 管理员 |
| 次要参与者 | 学生、教师 |
| 触发条件 | 管理员需要维护选课运行阶段、平台用户或查询操作记录 |
| 前置条件 | 管理员已登录并通过管理员权限校验 |
| 后置条件 | 管理配置和用户变更生效，相应操作形成可查询的审计记录 |

主成功流程：

1. 管理员进入管理端查看平台概况、用户和课程运行状态。
2. 管理员配置学期选课阶段、开放时间及对应操作规则。
3. 系统保存配置，学生端选课状态按新阶段生效。
4. 管理员查询用户列表和指定用户的操作记录。
5. 管理员在权限和业务约束允许时执行用户管理操作。
6. 系统记录管理员操作，供后续审计和问题定位。

备选或异常流程：

- 普通学生或教师访问管理接口时返回拒绝结果，前端不展示管理员功能。
- 开始时间晚于结束时间、阶段值无效等配置不能保存。
- 删除仍有关联教学数据的用户时，系统应拒绝或按明确约束处理，不能留下孤立记录。
- 审计记录不存在时返回空结果；系统故障时不得返回其他用户的敏感信息。

可验证结果：

- 选课阶段配置修改后 `/enrollment/status` 与实际可执行操作一致。
- 管理员可以查询授权范围内的用户和审计记录。
- 非管理员访问管理接口得到 403 或前端重定向，管理员操作能够被追踪。

实现与测试索引：`backend/src/routes/admin.ts`、`backend/src/routes/auth.ts`、`backend/src/routes/enrollment.ts`；`TC-ADMIN-001` 至 `TC-ADMIN-003-UI`、`TC-ENROLL-001`、`TC-ENROLL-006`。
