## 2. 数据表归属草案

### 2.1 course-service

负责身份、课程、选课、教学内容和通知，共 14 个现有模型：

`User`、`Course`、`CourseAnnouncement`、`AnnouncementMark`、`AnnouncementRead`、`SiteNotification`、`CourseMaterial`、`MaterialFavorite`、`Class`、`Enrollment`、`EnrollmentWaitlist`、`EnrollmentLog`、`EnrollmentPeriod`、`TimetableConfirmation`。

### 2.2 homework-grade-service

负责作业生命周期和成绩汇总，共 9 个现有模型：

`Homework`、`HomeworkAttachment`、`HomeworkRevision`、`HomeworkSubmission`、`HomeworkSubmissionVersion`、`HomeworkStudentFile`、`HomeworkRedoRequest`、`HomeworkKnowledgeAnalysis`、`HomeworkQuestion`。

当前 `Course` 模型中的作业/实验成绩权重应迁移为 homework-grade-service 管理的独立 `GradingConfig`，避免成绩服务直接修改课程服务数据库。

### 2.3 lab-practice-service

负责实验、评测、练习和讨论，共 15 个现有模型：

`PracticeKnowledgeTag`、`LabSet`、`LabReminderSent`、`Lab`、`LabFile`、`TestCase`、`Submission`、`PracticeQuestion`、`PracticeSession`、`PracticeSessionItem`、`PracticeQuestionFeedback`、`WrongBookEntry`、`DiscussionPost`、`DiscussionComment`、`DiscussionAttachment`。

三个服务的模型数量合计 38，与当前 Prisma Schema 一致。

## 3. 目标服务职责

| 服务 | 负责用例 | 核心职责 | 不负责 |
| --- | --- | --- | --- |
| course-service | UC01—UC04、UC10 | 用户认证、课程、选课、公告、资料、通知和管理配置 | 不直接查询作业、实验、练习表 |
| homework-grade-service | UC05、UC09 | 作业、提交、批改、迟交、重做、成绩权重和综合成绩 | 不直接查询课程、选课或实验表 |
| lab-practice-service | UC06—UC08，向 UC09 提供实验成绩 | 实验集、代码评测、练习、错题和讨论 | 不直接查询课程、选课或通知表 |

API 网关、PostgreSQL、Redis 和评测 Worker 不计入三个业务服务。评测 Worker 继续作为 lab-practice-service 的异步执行组件。

## 4. 建议接口边界

### 4.1 course-service 对内提供

| 方法与路径 | 用途 | 调用方 |
| --- | --- | --- |
| `GET /internal/users/:userId` | 获取最小用户信息和角色 | homework、lab |
| `GET /internal/courses/:courseId` | 获取课程名称、状态和教师 | homework、lab |
| `GET /internal/courses/:courseId/access/:userId` | 判断教师归属或学生选课权限 | homework、lab |
| `GET /internal/courses/:courseId/enrollments` | 获取课程学生 ID 列表 | homework、lab |
| `POST /internal/notifications` | 创建站内通知，要求幂等键 | homework、lab |

### 4.2 homework-grade-service 对内提供

| 方法与路径 | 用途 | 调用方 |
| --- | --- | --- |
| `GET /internal/courses/:courseId/homework-summary` | 返回课程作业完成与成绩汇总 | course/dashboard |
| `GET /internal/courses/:courseId/users/:userId/homework-grade` | 返回单个学生作业成绩 | course、grade 聚合 |
| `GET /internal/homework/:homeworkId` | 返回作业最小信息 | 其他经批准的服务 |

### 4.3 lab-practice-service 对内提供

| 方法与路径 | 用途 | 调用方 |
| --- | --- | --- |
| `GET /internal/courses/:courseId/lab-summary` | 返回课程实验完成汇总 | course/dashboard |
| `GET /internal/courses/:courseId/users/:userId/lab-grade` | 返回单个学生实验成绩 | homework-grade |
| `GET /internal/labs/:labId` | 返回实验最小信息 | 其他经批准的服务 |

## 5. 跨服务调用规则

1. 业务表只能由归属服务直接读写；其他服务必须调用接口或消费事件。
2. 跨服务查询默认设置 1—2 秒超时，失败时返回预先设计的部分结果或明确错误。
3. 通知创建使用幂等键，允许重试，不能因通知失败回滚已经完成的核心业务。
4. 成绩汇总调用实验服务失败时，返回“实验成绩暂不可用”的部分结果，作业服务不得崩溃。
5. 认证信息由网关传递，服务仍需验证签名和角色；禁止仅信任前端传入角色。
6. 跨服务写操作必须记录请求 ID；重复请求不能产生重复提交、重复通知或重复成绩。

## 7. 拆分前必须解决的耦合

1. `dashboard.ts` 和 `admin.ts` 当前直接统计课程、作业、实验多个领域的数据，需要改为接口聚合。
2. 作业、实验、讨论路由当前直接查询 `Enrollment` 和 `Course`，需要改为调用 course-service 权限接口。
3. 多个领域当前直接写入 `SiteNotification`，需要统一调用通知接口或发布事件。
4. 成绩权重目前存放在 `Course`，应迁移为独立成绩配置表。
5. Prisma 关系中的跨域外键拆分后只保留业务 ID，不建立跨 Schema 外键和联表查询。
6. 每个服务需要独立的健康接口、Dockerfile、测试命令、镜像版本和 Kubernetes Deployment。
