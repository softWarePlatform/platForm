## 1. 项目分层对应关系

课程要求中的常见分层在本项目中的实际落点如下：

| 课程概念 | 本项目实现 | 主要位置 |
|---|---|---|
| Controller | Fastify Route，负责参数接收、权限入口和 HTTP 响应 | `backend/src/routes/` |
| Service | TypeScript 业务函数，负责规则、状态转换和流程编排 | `backend/src/lib/` |
| Repository / DAO | Prisma Client 及其查询调用 | `backend/src/lib/prisma.ts`、各 Route/Service |
| Entity | Prisma 数据模型 | `backend/prisma/schema.prisma` |
| DTO / Validation | TypeScript 类型、Zod Schema、Route Schema | `backend/src/lib/`、`backend/src/routes/` |
| 异步 Worker | 队列消费、代码评测 | `judge-worker/src/` |

## 6. 补测选择原则

1. 优先测包含条件分支、状态变化、日期边界和金额/分数计算的业务函数。
2. 每个核心套件至少包含正常路径、重要异常路径和边界条件。
3. 不为简单 getter、纯转发 Route 或第三方库行为堆砌低价值测试。
4. 数据库、队列、文件系统等协作行为放入 Integration/API 测试，不强行写成脆弱的单元 Mock。
5. 8 月 26 日 P0 的四个核心套件已完成；P1 项作为 8 月 27 日 API 与集成补测输入。
