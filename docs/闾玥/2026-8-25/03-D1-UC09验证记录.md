## 3. 当前成绩计算口径

| 指标 | 当前实现 |
| --- | --- |
| 单实验题成绩 | 该学生该题历次提交的最高非空分数 |
| 实验集均分 | 集内已有分数题目的算术平均；无分题目不进入分母 |
| 课程实验均分 | 有 `setAverage` 的实验集均分再做算术平均 |
| 作业均分 | `graded=true` 且分数非空的作业分数算术平均 |
| 总评 | `(labAverage ?? 0) × labWeight + (homeworkAverage ?? 0) × homeworkWeight`；两类均为空时为 `null` |
| 排名 | 总评分降序后按数组序号 `i+1`；同分不并列 |
| 分布 | `<60`、`60–69`、`70–79`、`80–89`、`90+`；无总评单列 |

重要边界：只有一类有成绩时，另一类按 0 计算，已有类别仍只乘其原权重，不会自动归一。例如实验为空、作业均分 80、作业权重 0.4，则总评为 32，而不是 80。

## 6. 学生成绩可见性缺陷

教师成绩册中的作业项包含 `graded` 和 `released`。学生 CSV 的分项显示也会在 `released=false` 时隐藏具体作业分数，显示“已批改（成绩待发布）”。但是 `loadGradebook` 计算 `homeworkAverage` 时只筛选 `graded`，没有筛选 `released`。

因此学生通过以下位置仍能观察到未发布分数的影响：

- `GET /grades/me` 的 `summary.homeworkAverage`；
- `GET /grades/me` 的 `summary.totalScore`；
- 学生总评页面展示的作业均分和总评；
- 个人 CSV 的课程总览行；
- 排名也可能随未发布分数变化。

这与“作业具体分数仅在教师发布后显示”的接口注释和 CSV 文案不一致。

### BUG-D1-LY-UC09-001：未发布作业分数泄露到学生汇总

| 项目 | 内容 |
| --- | --- |
| 严重级别 | **P1** |
| 预期 | 未发布作业不影响学生可见的作业均分、总评和排名，或统一显示为暂不可用 |
| 实际 | 所有 `graded=true` 的分数均进入汇总，无论 `released` 是否为真 |
| 影响 | 学生可从均分、总评和排名变化推断未发布成绩 |
| 建议 | 教师成绩册保留全部已批改分数；学生视图计算时仅纳入 `graded && released`，并为学生独立生成排名；或者课程统一发布总评后再开放汇总 |
| 修复状态 | **代码已修复，待数据库/API 回归后关闭** |
| 修复实现 | 新增 `computeHomeworkAverage()` 的 `all-graded/released-only` 口径；学生 `/grades/me` 与个人 CSV 使用 `released-only`，教师成绩册保持 `all-graded` |
| 自动验证 | `grade-summary.test.ts` 已验证教师包含未发布成绩、学生排除未发布成绩、仅有未发布成绩时学生均分为 `null`；后端 TypeScript 构建通过 |

## 7. 既有自动化测试缺口

### BUG-D1-LY-UC09-002：学生成绩测试恒通过

`step6-system-test.mjs` 当前逻辑的两个分支都调用 `pass`：

```text
(gme.j?.courses?.length ?? 0) > 0
  ? pass("TC-GRADE-002")
  : pass("TC-GRADE-002", "接口正常")
```

即使接口错误地返回空课程列表，该测试仍通过。应改为检查 HTTP 200、课程 ID 存在、权重和为 1、总评公式正确，并与教师成绩册的同一学生逐字段比对。

### BUG-D1-LY-UC09-003：权重测试污染配置

测试先读取原权重到 `gc`，随后更新为 0.55/0.45，但没有使用 `gc` 恢复配置。这会改变后续演示和其他测试的成绩。测试应使用 `try/finally` 恢复原值，并验证恢复成功。
