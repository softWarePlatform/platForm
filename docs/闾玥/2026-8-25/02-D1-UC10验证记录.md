## 6. 操作记录核查

### 6.1 已实现的选课日志

`EnrollmentLog` 保存 `userId`、`courseId`、`action`、`operatorId?`、`note?`、`createdAt`，并按用户/课程和时间建立索引。当前枚举包括：

`ENROLL`、`DROP`、`WAITLIST_JOIN`、`WAITLIST_LEAVE`、`WAITLIST_PROMOTED`、`ADMIN_ENROLL`、`ADMIN_DROP`、`ADMIN_DELETE_USER`、`TIMETABLE_CONFIRM`、`COURSE_CREATE`。

管理员特殊加退课会传入当前管理员 ID，因而日志能区分目标学生与操作者。学生自己的 `GET /enrollment/logs` 以及管理员的 `GET /admin/users/:userId/logs` 都能读取这些记录。

### 6.2 删除用户记录不一致

`ADMIN_DELETE_USER` 已存在于 Prisma 枚举，但 `DELETE /admin/users/:userId` 实际没有写 `EnrollmentLog`，而是在删除事务中给当前管理员创建：

- `SiteNotification.type = ADMIN_ACTION`
- `title = 删除用户`
- `body = 被删用户名称和邮箱`

这会造成三个问题：

1. 删除操作与选课日志分属两套数据源；
2. `EnrollmentLog.userId` 外键为级联删除，即便写目标用户日志，删除用户后记录也会消失；
3. 通知不是不可篡改审计记录，且没有明确结构化目标 ID、结果、请求 ID和失败原因。

因此现有 `/admin/audit` 只能视为管理员通知展示，不能完全替代操作审计。

## 7. 缺陷记录

### BUG-D1-LY-UC10-001：缺少用户启用/禁用状态管理

| 项目 | 内容 |
| --- | --- |
| 严重级别 | **P1**（UC10 验收主流程缺失） |
| 预期 | 管理员能启用/禁用用户；禁用用户不能登录或继续使用旧令牌；动作进入审计记录 |
| 实际 | `User` 无状态字段；管理端只支持列表、日志和永久删除 |
| 影响 | 无法通过非破坏方式冻结异常账号，“用户状态正确”不可验证 |
| 建议 | 增加 `UserStatus(ACTIVE/DISABLED)`、`disabledAt`、`disabledById`、`disabledReason`；增加 `PATCH /admin/users/:id/status`；登录和 JWT 守卫都检查状态 |

### BUG-D1-LY-UC10-002：删除用户未进入统一审计日志

| 项目 | 内容 |
| --- | --- |
| 严重级别 | **P2** |
| 预期 | 删除用户产生不可随目标用户删除而消失的 `ADMIN_DELETE_USER` 审计记录 |
| 实际 | 枚举存在但未使用；操作只生成 `ADMIN_ACTION` 通知 |
| 影响 | 审计数据不统一，无法可靠追踪操作者、目标、请求和执行结果 |
| 建议 | 新建独立 `AdminAuditLog`，使用字符串快照保存操作者/目标信息和结构化 `metadataJson`；审计表不对目标用户使用级联删除 |

## 8. 建议修复后的回归清单

1. 管理员把选课阶段从开放改为 `CLOSED`，学生选课返回 403；再恢复原阶段并核对数据库值。
2. 管理员在 `CLOSED` 阶段为测试学生加课、退课，分别核对 `ADMIN_ENROLL`、`ADMIN_DROP` 的 `operatorId`。
3. 管理员禁用测试学生；新登录被拒绝，已签发令牌调用受保护接口也被拒绝；重新启用后恢复。
4. 非管理员调用阶段配置、用户列表、状态修改、审计接口均返回 403。
5. 自删和删除最后一名管理员均返回 400，用户与审计数据不发生变化。
6. 删除普通测试用户后，`AdminAuditLog` 中的操作者、目标快照、时间、结果仍可查询。
7. 所有测试使用临时用户/选课数据，并在结束时恢复原选课期配置。
