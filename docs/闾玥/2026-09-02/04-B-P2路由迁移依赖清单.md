# B：P2 路由迁移依赖清单与兼容说明

## 当前结论

`lab-practice-service` 初始有 7 个直接 Backend 依赖：6 个 UC06—UC08 路由入口和 1 个
Judge Dispatcher。递归分析后实际依赖闭包为 39 个文件。直接复制这些文件不能形成独立服务，
因为旧代码还会直接查询 `Course`、`Enrollment`、`User`、`SiteNotification`，并通过 Prisma
relation `include` 隐式读取外部实体。

UC06 的 `lab-sets`、`labs`、`lab-files`、`lab-overview` 和 Judge Dispatcher 已完成本地迁移并切换入口；
UC07、UC08 兼容入口继续使用旧 Backend 路由，确保公共 API 不变。旧实现未删除；
只有某个领域完成本地迁移、契约测试和 Gateway 验证后，才切换该领域入口。

- 公共能力：Auth/JWT、Config、Prisma、Course Access、Role Feedback、Platform LLM。

## 必须先补齐的跨服务接口

1. 根据 `courseId/userId` 返回课程访问权、教师身份、选课状态和班级 ID；
2. 批量获取用户 `id/name/email/role`，替代 Prisma `include: { user: ... }`；
3. 获取课程基本信息和教师 ID，替代 Prisma `include: { course: ... }`；
4. 分页获取课程名单；
5. 幂等写入课程通知，替代直接写 `SiteNotification`；
6. 明确 401、403、404、429、超时和 503 的错误映射。

## 安全迁移顺序

1. 在 Lab 内建立 Auth、Config、Prisma、Course Client、Notification Client；
2. 迁移 `lab-sets`，通过 Course API 替换课程和名单查询；
3. 迁移 `labs`、`lab-files`、`lab-overview`、Judge Dispatcher；
4. 迁移 `practice` 及其领域库；
5. 迁移 `discussions`，用用户批量接口组装作者信息并用通知 API 写通知；
6. 每迁完一组就切换 App 注册入口并运行单元、API、数据库和 Gateway 测试；
7. 全部切换后删除 `tsconfig`、Dockerfile 和源码中的 Backend 依赖；
8. 验收搜索结果必须为零，再进入数据迁移阶段。
