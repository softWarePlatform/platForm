## 4. 排障顺序

出现前端 `ECONNREFUSED` 或 502 时，按以下顺序排查：

1. `docker compose ps -a` 确认 migrate 是否 `Exited (0)`、API 是否 healthy；
2. 查看 `docker compose logs --tail 100 migrate api`；
3. 检查 `/health/live`，判断 API 进程是否启动；
4. 检查 `/health/ready`，判断 PostgreSQL 与 Redis 是否就绪；
5. 查看 Nginx 日志，确认 upstream 名称为 `api:3000`；
6. 最后再检查浏览器缓存、SSE 和前端页面。

不要先删除卷或重新 seed。删除数据只能在确认数据可丢弃后由用户手工执行。

## 5. 本次网络故障与恢复记录

执行命令：

```powershell
docker compose build --progress=plain
```

初次失败位置包括官方基础镜像 manifest、npm 仓库和 Debian 软件源，主要错误：

```text
Head "https://registry-1.docker.io/v2/library/nginx/manifests/1.27-alpine": EOF
Head "https://registry-1.docker.io/v2/library/node/manifests/24-bookworm-slim": EOF
Head "https://registry-1.docker.io/v2/library/node/manifests/24-alpine": EOF
npm error code ECONNRESET
502 Bad Gateway
```

复核命令：

```powershell
docker pull nginx:1.27-alpine
```

初次复核同样返回 EOF。用户检查 Docker Desktop 代理后再次拉取，结果为：

```text
Status: Downloaded newer image for nginx:1.27-alpine
docker.io/library/nginx:1.27-alpine
```

随后项目增加 npm/apt 重试并采用顺序构建，最终完整 `docker compose build --progress=plain` 退出码为 0。结论：初始阻塞属于外部网络/代理波动；最终镜像构建和运行均已验证通过。
