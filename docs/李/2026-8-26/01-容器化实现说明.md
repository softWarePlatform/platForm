# 容器化实现说明

## 1. 项目实际技术栈

附件中的 Maven、JAR 和 OpenJDK 命令仅为通用示例，本项目实际使用：

| 模块 | 技术 |
| --- | --- |
| 前端 | React 19、TypeScript、Vite 6 |
| 后端 | Node.js 24、Fastify 5、TypeScript |
| 数据库 | PostgreSQL 16、Prisma 6 |
| 缓存与队列 | Redis 7、BullMQ |
| 评测 | 独立 Node.js Worker，运行环境包含 Python 3 |
| Web 入口 | Nginx 1.27 |

因此数据库交付以 `schema.prisma + migrations + seed.ts` 为准，不重复维护容易失真的 `schema.sql` 和 `data.sql`。

## 2. 容器拓扑

| 服务 | 镜像/构建来源 | 职责 | 对外端口 |
| --- | --- | --- | --- |
| `db` | `postgres:16-alpine` | 业务数据库 | 默认 `5433` |
| `redis` | `redis:7-alpine` | 队列和缓存 | 默认 `6379` |
| `migrate` | `backend/Dockerfile` 的 `build` 阶段 | 一次性执行 `prisma migrate deploy` | 无 |
| `seed` | `backend/Dockerfile` 的 `build` 阶段 | 可选写入演示数据，属于 `tools` profile | 无 |
| `api` | `backend/Dockerfile` 的 `runtime` 阶段 | Fastify API | 仅容器网络 `3000` |
| `judge-worker` | `judge-worker/Dockerfile` | 消费评测队列 | 无 |
| `nginx` | `nginx/Dockerfile` | 前端静态资源及反向代理 | 默认 `80` |

浏览器只访问 Nginx：

- 页面：`http://localhost`
- API：`http://localhost/api/...`
- 健康检查：`http://localhost/health/live`、`http://localhost/health/ready`

## 3. 本次修正内容

### 3.1 后端镜像

- 移除 `backend/package.json` 中未被代码使用的 `teaching-platform: file:..` 依赖，避免 `./backend` 独立构建时引用构建上下文之外的父目录。
- 构建阶段安装开发依赖、生成 Prisma Client 并编译 TypeScript。
- 运行阶段只安装生产依赖，不再通过 `npx` 临时下载 Prisma CLI。
- 迁移从 API 启动命令中分离，避免 API 扩容时多个实例同时执行迁移。
- 上传根目录固定为 `/app/uploads`。

### 3.2 Worker 镜像

- 使用 `package-lock.json` 和 `npm ci`，使依赖安装可重复。
- 构建阶段生成 Prisma Client，运行阶段直接复用生成结果。
- 删除运行阶段重复执行的 `prisma generate`。
- 保留 Python 3，用于 Python 实验评测。
- 构建阶段安装 OpenSSL，使 Prisma 在 Debian Bookworm 中生成 `debian-openssl-3.0.x` 查询引擎。
- 与 API 挂载同一个 `/app/uploads` 卷，使 Worker 能读取学生上传的源文件。

### 3.3 前端与 Nginx

- 使用锁文件执行 `npm ci`，构建失败时不再回退到不确定的 `npm install`。
- 保留 React Router 的 `index.html` 回退。
- `/api/` 转发到 `api:3000` 并去除 `/api` 前缀。
- 对 `/api/notifications/events` 关闭代理缓冲，并将读取超时提高到 1 小时，适配 SSE 长连接。

### 3.4 Compose

- PostgreSQL、Redis、API、Nginx 均有健康检查。
- `migrate` 等待数据库健康后执行，API 和 Worker 等待迁移成功。
- Nginx 等待 API 健康后启动。
- 增加三个持久卷：`pgdata`、`redisdata`、`api_uploads`。
- seed 独立放入 `tools` profile，不会在普通 `docker compose up` 时自动清库。
- 宿主机端口可通过 `.env` 覆盖。

### 3.5 构建上下文

根目录新增 `.dockerignore`，排除：

- Git 元数据；
- 各模块的 `node_modules`、`dist` 和缓存；
- 本地环境变量；
- 文档、测试结果、视频、PDF 和本地上传文件；
- Worker 和前端构建不需要的其他大文件。

### 3.6 网络波动容错

- Dockerfile 中的 npm 安装使用 BuildKit cache mount 复用 `/root/.npm`。
- npm 明确配置 5 次获取重试及退避时间。
- Worker 的 apt 安装配置 3 次获取重试。
- 这些修改只提高镜像构建稳定性，不改变依赖版本或业务运行逻辑。

## 4. 数据库初始化原则

### 普通启动

普通启动只执行迁移，不自动写入或重置演示数据：

```text
db healthy → migrate exited 0 → api/worker → nginx
```

### 演示数据初始化

`backend/prisma/seed.ts` 会：

1. 清空 `public` schema 下除 `_prisma_migrations` 外的业务表；
2. 删除已有演示上传目录；
3. 重新写入课程、用户、作业、实验和测试 fixture。

因此 seed 只能在明确需要重置演示环境时手工执行，不能放入 API 默认启动命令。
