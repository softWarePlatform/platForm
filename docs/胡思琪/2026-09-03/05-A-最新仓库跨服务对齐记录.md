## A 本轮代码与测试变更

1. 将 Dashboard 的 Lab 上游调用从未被 B 提供的 `POST /internal/dashboard/course-summaries:batch` 替换为冻结的 `GET /internal/courses/:courseId/lab-gradebook`。
2. Dashboard 只有在 B 返回 `labStatus: OK` 时暴露实验摘要；非 2xx、超时、网络错误或异常响应统一降级为 `UNAVAILABLE/null`。
3. 更新 A 的上游契约测试，精确断言 Lab 请求路径、`x-internal-service-token` 和 `x-request-id`。
4. 为已有的 `POST /internal/users:batch` 补充实际 API 冒烟断言，并让固定种子课程的选课冒烟可重复运行：首次 `201` 与已选课的 `409` 均继续验证后续接口。

## 不以“已对齐”掩盖的边界

- 本轮没有同时启动 A、B、C，所以尚未证明 A Dashboard 在同一次请求中同时得到 `homework: OK` 与 `lab: OK`；这是进程级联调待办，而不是 A 代码缺失。
- B 的 gradebook 路由调用 A 的名单函数时没有传入原请求 ID，C 的内部 Course 请求也大多没有透传入口请求 ID；接口本身可用，但分布式追踪链不完整。
- B 的 Lab 数据迁移与独立边界、Gateway 实际部署和全服务故障注入不属于 A 的代码职责，列入待办并由相应负责人完成。
